Entry Point & Call Graph

src/main.c contains the main() function. The high-level flow is:

main(argc, argv) | +--> default_params() // params.h — set defaults +--> parse CLI args (--N, --L, --steps, --puncture, --rk, ...) +--> backend_init() // backend.h — no-op for CPU +--> grid_alloc(N, L, rk_method) // grid.c — page-aligned SoA arrays | +--> Initial Data: | if punctures: set_brill_lindquist(g, n_bh, masses, centers) | else: set_flat_spacetime(g) | +--> compute_constraint_l2(g) // initial Hamiltonian check | +--> Time Evolution Loop (step = 1 .. num_steps): | | | +--> rk4_step(g, &p, ccz4_rhs_point, apply_sommerfeld, dt) | | | | | +--> [CK45 or Classic RK4 dispatch] | | | for each RK stage: | | | +--> backend_compute_rhs(rhs, fields, g, p, ccz4_rhs_point) | | | | | | | | | +--> OpenMP parallel z,y,x loop: | | | | ccz4_rhs_point(rhs, src, g, p, i, j, k) | | | | +--> load fields into locals | | | | +--> fd_d1, fd_d2, fd_d2_mixed, fd_adv // derivatives | | | | +--> compute_inverse_sym // h^{ij} | | | | +--> compute_christoffel // Gamma^i_{jk} | | | | +--> Ricci tensor with Z terms | | | | +--> CCZ4 RHS (chi, h, K, A, Theta, Gamma) | | | | +--> Moving puncture gauge (lapse, shift, B) | | | | +--> add_ko_dissipation // 6th-order KO | | | | | | | +--> apply_sommerfeld(rhs, fields, g) // boundary conditions | | | +--> ck45_update / axpy_fields // field update | | | | | +--> enforce_algebraic(g) | | +--> det(gambar) = 1 rescaling | | +--> tr(Abar) = 0 projection | | +--> chi > 0, lapse > 0 floor | | | +--> periodic: compute_constraint_l2(g) + print | +--> optional: output_1d_slice(g, step, time) | +--> grid_free(g) +--> backend_cleanup()

Data Flow Through a Single Timestep

Field data lives in Struct-of-Arrays layout: 25 contiguous double* arrays, one per evolved variable. A single CK45 timestep proceeds as follows:

CK45 Step (5 stages, 3 memory blocks: U=fields, F=rhs, dU=scratch) dU = 0 (zero scratch arrays) for s = 0..4: // 1. Compute RHS from current state [grid memory] U[f][idx] ----> backend_compute_rhs ----> F[f][idx] | OpenMP collapse(2) on z,y loops for each interior point (i,j,k): ccz4_rhs_point reads U via FD stencils (neighbors +-3) writes F at (i,j,k) // 2. Apply boundary conditions to RHS [ghost zones] apply_sommerfeld overwrites F in ghost cells Sommerfeld: df/dt = -(x^i/r) d_i f + (f_asym - f)/r // 3. Fused CK45 update (OpenMP parallel for) for each f, each point i: dU[f][i] = A[s] * dU[f][i] + dt * F[f][i] U[f][i] += B[s] * dU[f][i] // 4. Algebraic enforcement (OpenMP collapse(2) on k,j) for each point: rescale h_ij so det(h) = 1 project A_ij to be trace-free floor chi > 1e-12, lapse > 1e-12

Memory Layout Detail

Each "block" (fields, rhs, scratch, optionally accum) is a single contiguous allocation of NUM_FIELDS * npoints doubles. Per-field pointers index into these blocks at offsets of f * npoints. This design enables efficient GPU mapping with a single omp target enter data per block.

fields_block:  [ field_0: Ntotal^3 doubles | field_1: Ntotal^3 doubles | ... | field_24 ]
                ^                             ^
                g->fields[0]                  g->fields[1]

Grid indexing:  IDX(g, i, j, k) = k * Ntotal^2 + j * Ntotal + i
                x is innermost (unit stride), z is outermost
                Ghost width = 4 on each side
                N padded to next multiple of 16 for cache alignment

Key Design Patterns

1. Struct-of-Arrays (SoA) Layout

Every field is a contiguous double* array of Ntotal^3 elements. The RHS function loads needed values into local variables at each grid point, computes, then stores back. This is cache-friendly for the triple-loop backend and maps directly to GPU kernels.

2. Field Enum (Append-Only)

All 25 evolved fields are indexed by an enum in fields.h: FIELD_CHI, FIELD_H11, ..., FIELD_B3, NUM_FIELDS. The enum ordering is append-only (Critical Invariant #5). Symmetric tensors use a sym_table[3][3] mapping to flat indices 0..5.

3. Backend Abstraction

backend_compute_rhs() owns the loop structure. The CPU backend uses #pragma omp parallel for collapse(2) and calls ccz4_rhs_point via function pointer. The GPU backend calls it directly (no function pointers on GPU). Physics kernels never include platform headers.

4. Per-Point RHS Function

ccz4_rhs_point(rhs, src, g, p, i, j, k) is self-contained: it reads from src arrays using FD macros, computes the full CCZ4 RHS including gauge and dissipation, and writes to rhs arrays. This matches GRChombo's rhs_equation() pattern.

5. FD Macro Discipline

All finite differences go through fd_d1(), fd_d2(), fd_d2_mixed(), fd_adv(), and fd_ko() in finite_diff.h. No hand-coded stencils anywhere (Critical Invariant #3). Each takes (field_ptr, idx, stride, dx) — direction-independent via stride parameter.

6. Algebraic Enforcement

After every full RK step: det(gambar) = 1 enforced by rescaling h_ij, and tr(Abar) = 0 enforced by projection. Also floors chi > 1e-12 and lapse > 1e-12.

7. Physics Naming Conventions

Suffix _dd = covariant, _uu = contravariant, d1_ = first derivative, d2_ = second derivative. Symmetric 3x3 tensors stored as double[3][3]. Loop macros: FOR1(i), FOR2(i,j), FOR3(i,j,k).

Module: evolution/ Implemented & Tested

The CCZ4 right-hand-side equations and Kreiss-Oliger dissipation. This is the physics core of the code.

evolution/ccz4_rhs.h / ccz4_rhs.c — Full CCZ4 RHS at a single point

Computes the complete CCZ4 right-hand-side for all 25 fields at one grid point (i,j,k). Steps: load fields, compute 1st/2nd/advection derivatives, inverse metric, Christoffel symbols, Z vector, Ricci tensor with Z terms, covariant lapse derivatives, CCZ4 evolution equations, moving puncture gauge, store RHS, add KO dissipation.

~430 lines. The single most complex function in the codebase. Approximately 4 KB of stack locals (derivative tensors, Christoffel symbols, Ricci tensor components).

FunctionDescription
ccz4_rhs_point(rhs, src, g, p, i, j, k)Full CCZ4 RHS including gauge and dissipation. GPU-annotated with #pragma omp declare target.

References: arXiv:1106.2254 (CCZ4 equations), GRChombo CCZ4RHS.impl.hpp:60-227, CCZ4Geometry.hpp (Ricci), MovingPunctureGauge.hpp (gauge)

Depends on: fields.h, grid.h, params.h, finite_diff.h, tensor_utils.h, dissipation.c (via extern)
Depended on by: backend_cpu.c, backend_gpu.c, main.c, all tests

evolution/dissipation.c — Kreiss-Oliger dissipation (+CAKO, per-field sigma)

Adds 6th-order Kreiss-Oliger dissipation to each field's RHS: rhs[f] += sigma_eff * sum_dir(fd_ko). Uses a 7-point stencil per direction. Called at the end of ccz4_rhs_point. With CAKO enabled, sigma_eff = sqrt(chi) * sigma_base suppresses dissipation near punctures. With per-field sigma, gauge fields (lapse, shift, B) get 0.99 while physical fields get 0.3.

FunctionDescription
add_ko_dissipation(rhs, src, g, p, i, j, k)Adds KO dissipation for all 25 fields. Supports CAKO + per-field sigma. GPU-annotated.
is_gauge_field(f)Returns 1 for lapse/shift/B fields (indices ≥ FIELD_LAPSE). Static inline.

Ref: arXiv:2404.01137, Eq. (20) (CAKO), text near Eq. (20) (per-field sigma)

Depends on: fields.h, grid.h, finite_diff.h
Depended on by: ccz4_rhs.c (via extern forward declaration)

Module: amr/ Stage 4.1 Complete (6 stages total)

Oct-tree block AMR implemented in 6 stages (see plan1.md). The architecture wraps each grid_t in a block_t with tree metadata, managed by a mesh_t. A meshblock_pack_t packs block data into contiguous GPU-friendly buffers. The physics code (ccz4_rhs_point) runs unchanged on each block. Stage 4 adds dynamic oct-tree refinement/coarsening with chi-gradient criterion and cross-level ghost exchange. Stage 4.1 introduces the AthenaK coarse-buffer architecture: each leaf block at level > 0 carries a coarse_buf (half-resolution grid_t) for block-local multilevel ghost fill with no cross-block writes. Restriction upgraded to 4th-order Lagrange throughout.

Key patterns copied from Athena++ (Stone et al. 2020) and AthenaK (Grete et al. 2024): LogicalLocation tree addressing, nblevel[3][3][3] neighbor level tables, child octant indexing n = ox1 + (ox2<<1) + (ox3<<2), Morton Z-order block sorting, MeshBlockPack GPU batching.

Coarse-Buffer Architecture (Stage 4.1, AthenaK pattern) — Implemented:

Each leaf block at level > 0 carries a coarse_buf grid_t at half resolution (N/2 cells, 2× dx). This enables block-local multilevel ghost exchange with no cross-block memory writes. The coarse_buf is allocated by coarse_buf_alloc() (fields-only, no RK arrays). The ghost_exchange_multilevel() function uses 5 phases:

ghost_exchange_multilevel(mesh_t *m) | +--> Phase 0+1: exchange_same_level(m, L) for L=0..max_level | Same-level neighbor exchange at each level (fills sibling ghosts) | +--> Phase 2: restrict_to_coarse_buf(b) for each fine leaf | 4th-order Lagrange: fine interior → own coarse_buf interior | w = {1/48, 23/48, 23/48, 1/48}, 3D tensor product (64 fine cells) | +--> Phase 3: fill_coarse_buf_ghosts(m) | For each fine leaf, for each of 26 neighbors: | Same-level nbr: exchange_grid_pair(buf ↔ buf) | Coarser nbr: copy_from_coarse_grid(buf ← coarse grid) | +--> Phase 3.5: fill_coarse_buf_boundary(b) | Quadratic extrapolation for domain-boundary ghost cells | Ensures prolongation stencil reads valid data at boundaries | +--> Phase 4: prolongate_from_own_coarse_buf(b) 5-point Lagrange interpolation: coarse_buf → fine ghost zones Skips directions already filled by same-level exchange (Phase 1)

4th-Order Restriction (Stage 4.1) — Implemented:

Restriction upgraded from 2nd-order (8-cell average) to 4th-order cell-average Lagrange. The 1D 4-point symmetric stencil covers fine positions {-3δ/2, -δ/2, +δ/2, +3δ/2} with weights derived by integrating Lagrange basis polynomials over the coarse cell. 3D: tensor product of 1D weights, 4³ = 64 fine cells per coarse cell. Falls back to 2nd-order when stencil exits grid bounds. Used in:

  • restrict_to_coarse_buf() — fine block interior → own coarse_buf (Phase 2 of ghost exchange)
  • restrict_child_into_parent() — child data → parent during coarsening (refine.c)
  • restrict_field() / restrict_all() — standalone fine→coarse restriction

Ref: ExaHyPE (arXiv:2504.15814) — matching restriction order to prolongation eliminates Hamiltonian violations at AMR boundaries. Fornberg, SIAM Review 40 (1998) — FD weight generation.

Noise Reduction (Stage 3, arXiv:2404.01137) — Implemented:

  • CAKO — Curvature-adjusted KO: sigma_eff = sqrt(chi) * sigma_base. Suppresses near punctures (chi→0). Eq. (20).
  • CAHD — Constraint-adjusted Hamiltonian damping: rhs_chi += 4*chi*C*CFL*dx*H (C=0.15). Eq. (26). NOT kappa1 modification.
  • SSL — Slow-start lapse: rhs_lapse += -W*h*exp(-t²/(2σ²))*(alpha-W). h=0.6M, σ=20M. Negligible after t~100M. Eq. (27).
  • Per-field sigma — sigma=0.99 for gauge (lapse, shift, B), 0.3 for physical (18 fields). All disabled by default.
