2. HIP Backend Implementation Guide

2.1 Why HIP Covers Everything

No need for separate CUDA and HIP backends. HIP covers both vendors:

  • BACKEND=hip HIP_PLATFORM=amd → hipcc calls amdclang++ → AMD GPUs
  • BACKEND=hip HIP_PLATFORM=nvidia → hipcc calls nvcc → NVIDIA GPUs

One backend, both vendors. Zero performance overhead on NVIDIA (HIP→CUDA translation is compile-time).

2.2 Architecture: Unity Build

The key insight: backend_hip.cpp #includes our physics .c files inside extern "C" {}. hipcc compiles everything as C++. Our C17 code is compatible. Zero changes to existing physics files.

// backend_hip.cpp
#include <hip/hip_runtime.h>
extern "C" {
#include "../evolution/ccz4_rhs.c"
#include "../evolution/maxwell_rhs.c"
#include "../evolution/dissipation.c"
#include "../boundary/sommerfeld.c"
#include "../amr/restriction.c"
#include "../amr/prolongation.c"
#include "../amr/block.c"
}
// ... __global__ kernel definitions + backend_* implementations

2.6 RHS Kernel: The Hard Part

The ccz4_rhs_point function uses ~5.3 KB stack per thread (derivative tensors, Christoffel symbols, Ricci tensor locals from 5 inlined sub-functions). This requires:

  • __launch_bounds__(128, 4) — limits occupancy to allow large stack
  • Block size of 128 threads (not 256 or 512)
  • At most 4 blocks per SM to keep stack within limits

The unity build approach means ccz4_rhs_point and all its sub-functions are visible in the same translation unit — the compiler can inline and optimize register usage across the entire call chain.

3. Fused RHS + Dissipation Analysis

3.1 Surprise: Dissipation is Already Fused

add_ko_dissipation is called at line 590 inside ccz4_rhs_point — not as a separate kernel launch. Both RHS and KO happen for the same point in the same function call. There is no separate pass at the backend level.

The real optimization is reducing redundant memory loads within the per-point computation.

3.2 The Real Opportunity: Fused Stencil Loaders

Currently, three separate loops over 3 spatial directions each load from the same stencil neighborhood:

LoopFunctionLoads per field per direction
1. First/second derivativesfd_d1_d27 points
2. Advectionfd_adv_up / fd_adv_down7 points
3. KO dissipationadd_ko_dissipation9 points

All three reach into the same {-4s, ..., +4s} stencil neighborhood. Merging into a single 9-point load:

Loads per field per direction
Current (three passes)7 + 7 + 9 = 23
Fused (one pass)9
Savings14 loads × 25 fields × 3 dirs = 1050 loads/point

3.3 EM KO Dissipation Bug BUG

Latent bug discovered: ccz4_rhs_point applies KO dissipation to all 31 fields (including EM fields 25–30), but then maxwell_rhs_point overwrites EM RHS fields, discarding their KO dissipation.

Result: EM fields run without dissipation in coupled runs.

Fix: Move KO call after Maxwell RHS stores, or accumulate KO separately and apply last.

6. AMR-CCZ4 Chain Audit for CCE

CCE (Cauchy-Characteristic Evolution) takes Cauchy data on a worldtube and evolves it on null hypersurfaces to future null infinity (scri+), producing exact asymptotic waveforms. This audit checks every link in Lattice's chain for CCE-quality data.

6.1 Link 1: Initial Data Solver PASS

Implementation: FAS multigrid with FMG + Newton-Gauss-Seidel, 8-color ordering. Solves to discretization accuracy O(dx4–dx6). FMG achieves this in ~1.14 V-cycles.

Key strength: Solver operates directly on AMR evolution mesh (no interpolation). Documented as 218,000x better near-field constraint quality vs copy approach.

CCE verdict: Initial constraint residual is at or below evolution truncation error. Will not pollute the evolution. Level-boundary restriction/prolongation errors are O(dx6), matching the FD scheme.

6.2 Link 2: AMR Prolongation (Coarse → Fine) PASS

Implementation: 6th-order cell-centered Lagrange via 7×7×7 tensor-product stencil. Weights derived via SymPy, verified bit-exact.

CodeProlongation Order
Lattice6th order
GRChombo4th order (Chombo default)
AthenaK5th order (N_ghost + 1)
BAM4th–6th order

CCE verdict: Matches or exceeds all major FD production codes. At the CCE worldtube radius (100M+), refinement boundary errors are negligible if the extraction sphere doesn't coincide with a level boundary.

6.3 Link 3: AMR Restriction (Fine → Coarse) PASS

Implementation: 6th-order cell-average restriction, 63=216 fine cells per coarse cell. Exact for polynomials through degree 5.

Noise concern: Slightly negative outer weights (-17/11520) are not monotonicity-preserving but this only matters for sharp features. In the wave zone (where the CCE worldtube sits), fields are smooth.

Key design strength: Matching prolongation/restriction orders (both 6th) prevents the "order mismatch" artifacts documented in ExaGRyPE (arXiv:2504.15814).

6.4 Link 4: Ghost Exchange PASS

Implementation: Multi-phase AthenaK-style coarse-buffer architecture: same-level exchange → restriction → coarse_buf ghost fill → boundary extrapolation → prolongation.

Order-of-operations: Carefully sequenced — all restrictions complete before coarse_buf exchange, all ghosts filled before prolongation. Same-level exchange is exact copy (zero error). Cross-level is 6th-order.

Minor weakness: Quadratic (3-point, O(dx2)) extrapolation for domain boundary ghost cells in coarse_bufs. Only affects blocks at the outer boundary, not the extraction region.

6.5 Link 5: CCZ4 RHS + Dissipation PASS +CAHD recommended

Implementation: 5 static inline sub-functions with scoped lifetimes. 6th-order KO with CAKO (sigma_eff = W * sigma_base). Per-field sigma (0.99 gauge, 0.3 physical).

Wave-zone dissipation check: For a GW with N_lambda = lambda/dx = 20 grid points per wavelength:

KO dissipation per crossing ~ sigma * (pi/N_lambda)^6 ~ 10^-8

This is negligible. For marginal resolution (N_lambda=10): ~10-5, still acceptable.

Recommended improvement: CAHD (Coarse-grid-Adjusted Hamiltonian Damping, C=0.15) would reduce extraction-zone Hamiltonian violations by ~5 orders of magnitude. Not a blocker, but significant quality improvement.

6.6 Link 6: Sommerfeld Boundary Conditions WEAK LINK

Implementation: 4th-order Sommerfeld radiative BCs with 5 adaptive stencil variants.

This is the weakest link in the chain for CCE.

  • Reflection coefficient: Decays as (k·R_boundary)-4. At R=500M with GW wavelength ~100M, reflections are ~10-4 to 10-6 of incident amplitude.
  • CCE worldtube interaction: Reflected waves arrive at worldtube (R_wt=100M) after t ~ 2×(R_boundary - R_wt). For R_boundary=500M, this is t ~ 800M. For a ~1000M merger simulation, this is marginal.
  • Production comparison: SpEC uses R ≥ 800M with higher-order absorbing BCs (HOBC). Recent arXiv:2402.12544 shows HOBC gives "impressively lower errors."

Mitigations:

  1. Outer boundary at R ≥ 800M (larger domain)
  2. CCE worldtube at R ~ 100–200M (far from boundary)
  3. Implement HOBC (higher-order absorbing boundary conditions)
  4. Or use PHE instead of CCE (less sensitive to boundary reflections)

6.7 Link 7: Waveform Extraction CRITICAL GAP

Ψ4 extraction is not yet implemented. No waveform extraction of any kind exists. This is the most urgent development need.

For CCE worldtube output, Lattice needs:

  1. Full spatial metric γij (available: h_ij × chi-1)
  2. Extrinsic curvature Kij (available: A_ij + (1/3)Kγ_ij)
  3. Lapse α and shift βi (available: evolved fields)
  4. Spatial derivatives of all above on extraction sphere
  5. Interpolation onto coordinate sphere (existing 4th-order Lagrange is adequate)
  6. Spin-weighted spherical harmonic decomposition
  7. Conversion to Bondi-Sachs variables (or use SpECTRE's PreprocessCceWorldtube)
  8. H5 output in SpECTRE CCE format (9 datasets: Beta, DrJ, DuR, H, J, Q, R, U, W)

PHE alternative: PHE only needs Ψ4 at finite radius (no full metric). Once Ψ4 extraction exists, PHE is simpler than CCE coupling and achieves < 0.05 rad phase difference from CCE.

Estimated effort: Ψ4 extraction: 2–4 weeks. Full worldtube output for SpECTRE CCE: 4–6 weeks additional.

6.8 Link 8: Time Integration (RK4 + Subcycling) PASS

Implementation: Classic RK4 (4th-order) with Berger-Oliger subcycling and quartic temporal interpolation at level boundaries.

Is RK4 sufficient? Yes. Overall convergence = min(spatial, temporal) = min(6, 4) = 4. At typical CFL numbers (dt ~ 0.25dx), the 4th-order temporal error coefficient is much smaller than the 6th-order spatial error coefficient. AthenaK also uses RK4 + 6th-order spatial and reports 4th-order waveform convergence.

Subcycling temporal interpolation: 4th-order quartic (5 constraints). Matches the RK4 time integration order. Same approach as Athena++ and GRChombo.

Bottom Line

Lattice's numerical infrastructure (6th-order FD, matched prolongation/restriction, FAS multigrid, CAKO dissipation) is at or above state of the art for finite-difference NR codes. The measured convergence order of ~6.5 exceeds what most production codes achieve.

The gaps are implementation completeness, not mathematical accuracy: no Ψ4 extraction, binary inspiral not yet converging, no CCE/PHE pipeline. The pragmatic path is: Ψ4 first → PHE → CCE worldtube output.

Closing the gaps to CCE-quality waveform production: ~6–8 months focused development. First Ψ4 waveforms: 4–6 weeks. PHE waveforms at null infinity: 3–4 months.

8. Implementation Specifics

Concrete implementation details for each gap identified in the chain audit. Two items (CAHD, SSL) are already implemented.

8.1 Ψ4 Extraction CRITICAL

New file: src/diagnostics/psi4.c + psi4.h (~800 lines total)

Three components:

ComponentLinesWhat
Point-wise Psi4~400E_ij, B_ij (Weyl tensor), NP tetrad, contraction
Sphere extraction~250Interpolate onto coordinate spheres at r=50,75,100M using existing interpolate.h
SH decomposition~150Spin-weight s=-2 harmonics, l_max=4–8, Gauss-Legendre quadrature

Reuses: tensor_utils.h (Christoffel, inverse metric), interpolate.h (4th-order Lagrange), finite_diff.h (d1/d2 stencils). AH finder (ah_finder.c) already does sphere interpolation + Christoffel computation — same pattern.

Cost: ~13.5 MFLOP per extraction (3 radii × 32×64 angular grid). Negligible vs one RHS eval (~1 GFLOP at N=128). Extract every 4–8 steps.

Effort: 3–5 days. Dependencies: none. Blocks PHE and CCE worldtube.

8.2 PHE (Perturbative Hyperboloidal Extraction)

New file: tools/phe_extract.c (~500–700 lines). Standalone post-processing tool.

Algorithm (arXiv:2508.05743): Solve 1+1 Regge-Wheeler-Zerilli equation on hyperboloidal slices to propagate Ψ4 from finite radius to scri+.

  • Input: Ψ4 mode time series from extraction (item 8.1), projected to RWZ master function
  • Solver: 1D RK4 in time, 4th-order FD in compactified radial coordinate
  • Output: Ψ4 at null infinity, gauge-invariant

Accuracy: < 0.05 rad phase difference from full CCE. Amplitude < 0.5%. Does not capture nonlinear memory.

Effort: 1–2 weeks (after Psi4). Dependencies: item 8.1.

8.3 CCE Worldtube Output

New file: src/io/cce_worldtube.c + cce_worldtube.h (~600–800 lines)

SpECTRE "metric modal" format — 30 HDF5 datasets:

DataDatasetsSource in Lattice
γij + Dr + Dt18h_ij/chi, FD radial deriv, analytic Dt from CCZ4 RHS
βi + Dr + Dt9shift, FD radial deriv, analytic Dt from gauge RHS
α + Dr + Dt3lapse, FD radial deriv, analytic Dt from gauge RHS

Each dataset = time series of spin-weighted SH coefficients (s=0, l_max=12–24). Requires Gauss-Legendre quadrature on extraction sphere + HDF5 library (first external dependency, or use Python converter).

Effort: 2–3 weeks. Dependencies: item 8.1 (sphere interpolation infrastructure).

8.5 CAHD ALREADY IMPLEMENTED

Implemented at ccz4_rhs.c:342–347. Adds -C * CFL * dx * H to dt(chi), where H = Hamiltonian constraint. Stronger damping on coarser AMR levels (CFL*dx scales with level).

Enable: --cahd CLI flag. Default off. Recommend flipping to default on for production.

Effort: 0 days.

8.6 Slow-Start Lapse ALREADY IMPLEMENTED

Implemented at ccz4_rhs.c:497–505. Gaussian-damped term drives lapse toward trumpet during early evolution, suppressing junk radiation.

Default ON. Parameters: h=0.6M, sigma_t=20M. Active for t < ~60M then decays to zero.

Effort: 0 days.

8.7 HOBC (Higher-Order Absorbing BCs)

New file: src/boundary/hobc.c + hobc.h (~800–1200 lines)

Solves auxiliary ODE systems per (l,m) mode at the boundary. Reflection coefficient: (kR)-2(L+1) with order L, vs (kR)-4 for Sommerfeld.

Architectural change: Current Sommerfeld is point-by-point (local). HOBC requires SH decomposition at boundary (global), auxiliary variable storage (~16K doubles), and coupling to RK4 for time integration of auxiliaries.

Alternative: Just double the domain size (R: 500M → 1000M). Costs ~8x memory on coarsest level but trivial to implement. With AMR, cost is moderate since only the coarsest level extends.

Effort: 3–4 weeks. Dependencies: benefits from SH code in item 8.1.
