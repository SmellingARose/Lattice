KO Dissipation Stability Analysis

Why the QNM publication test NaN's at t=14M, and how to fix it.

1. The Problem: Zero Ghost Margin

Kreiss-Oliger dissipation at the first interior cell reads ghost zone data. With 8th-order KO and 4 ghost cells, the stencil reaches the very first ghost cell — the one with the most interpolation error from AMR prolongation.

8th-order KO stencil at first interior cell (current — ZERO margin)

Ghost Zone (prolongated data) Interior (evolved data)
g0 g1 g2 g3 i0 i1 i2 i3 i4 i5 i6 … iN
← worst interpolation quality → exact

  9-point stencil reads ALL 4 ghost cells including g0 (lowest quality)  

6th-order KO stencil at first interior cell (1-cell margin)

Ghost Zone (prolongated data) Interior (evolved data)
g0 g1 g2 g3 i0 i1 i2 i3 i4 i5 i6 … iN
not read 7-point stencil →

  7-point stencil skips g0 — outermost ghost cell never touched  

The feedback loop (why it causes NaN)

Step N:  Prolongation fills g0 with interpolation error ε
         ↓
         KO dissipation at i0 reads g0 → amplifies ε by factor σ
         ↓
Step N+1: Restriction sends amplified error to coarser level
         ↓
         Prolongation re-interpolates → error grows as σ^N
         ↓
         At σ=1.0, error doubles every ~few steps → NaN by t=14M

4. Fix Options

Option A: Drop KO to 6th order for AMR runs

Code change Easy

Already supported: make FD_ORDER=4 selects 6th-order KO. Add a runtime flag --ko-order 6 or compile-time KO_ORDER=6 that uses the 6th-order KO stencil (7-point, half-width=3) with 6th-order FD. The 6th-order KO weights are already in finite_diff.h (lines 382–397).

Ghost margin: 1 cell. Matches GRChombo and AthenaK exactly.

Pros

  • Matches GRChombo/AthenaK/BAM — proven stable
  • 1-cell ghost margin eliminates the feedback loop
  • 6th-order FD with 6th-order KO is the industry standard
  • Can keep σ=1.0 (GRChombo does this successfully)
  • Tiny code change (select existing stencil)

Cons

  • Slightly less high-frequency damping than 8th-order
  • GRChombo has 8th-order commented out, suggesting they considered it

Option B: Level-dependent σ (BAM approach)

Parameter change Easy

CLI: --sigma 0.1 (or add level-dependent sigma: 0.1 on fine levels, 0.5 on coarse). No code change needed for uniform σ=0.1. Level-dependent requires ~20 lines.

Ghost margin: still 0. But the amplification factor drops 10×, so the feedback loop grows much slower and may not reach NaN in the simulation time.

Pros

  • Zero code change for uniform σ=0.1 (CLI flag only)
  • Matches BAM's proven configuration
  • Keeps 8th-order KO (better spectral properties)
  • Can test immediately without recompiling

Cons

  • Doesn't fix the root cause (zero margin)
  • σ=0.1 may under-damp noise on coarse levels
  • May need fine-tuning per simulation

Option C: Increase ghost width to 5

Code change Hard

Change GHOST_WIDTH from 4 to 5 in grid.h. Gives the 8th-order KO stencil a 1-cell margin. Keeps 8th-order KO + σ=1.0.

Pros

  • Keeps 8th-order KO + high σ (maximum damping capability)
  • 1-cell margin, same as GRChombo with 6th-order

Cons

  • Ripples through entire codebase: ghost exchange, prolongation (COARSE_BUF_GHOST changes), boundary conditions, memory layout
  • ~25% more memory per block (ghost volume grows)
  • More communication in ghost exchange
  • No other code uses ghost=5

Option D: All parameter fixes (match BAM exactly)

Parameter change Easy + Code change Easy

Combine Option A or B with constraint damping + gauge fixes:

--sigma 0.1          # BAM fine-level dissipation
--covariant 0        # non-covariant Z4 (kappa1*alpha near puncture)
--kappa1 0.02        # BAM/AthenaK constraint damping
--eta 2.0            # BAM Gamma-driver damping

Plus either drop KO to 6th (Option A) or keep 8th with low σ (Option B).

Pros

  • Matches BAM's exact proven configuration
  • Addresses ALL identified issues, not just KO
  • Non-covariant + κ1=0.02 = 17× less damping near puncture
  • η=2.0 = faster gauge settling (BAM-calibrated)
  • Most likely to "just work" since BAM demonstrated stability

Cons

  • Changes multiple parameters at once (harder to isolate effect)
  • Non-covariant Z4 is less clean mathematically than covariant
  • Lower σ may need CAKO/per-field sigma for binary inspirals

5. CCZ4 Formulation Mismatch (Critical Finding)

Lattice uses a hybrid CCZ4 configuration that no production code uses:

Configurationκ3κ1 prescriptionDamping at puncture (α→0)Used by
Standard Z4c 0.5 α × κ1 Vanishes (0.02 × 0.01 = 0.0002) BAM, AthenaK, CarpetX
Covariant CCZ4 1.0 constant κ1 Constant (0.1) — stable with κ3=1 GRChombo
Lattice (current) 0.5 constant κ1 Constant (0.1) — untested with κ3=0.5 Nobody else

Alic et al. 2013 (arXiv:1307.7391) tested all 4 combinations of (κ3, κ1 prescription). All were stable in their tests, but κ3=0.5 + constant κ1 is the least-tested combination — no production code adopted it. The concern: constant κ1=0.1 with κ3=0.5 gives strong damping that doesn't vanish at the puncture, but the weak Z coupling (κ3=0.5) may not provide enough constraint propagation to balance that damping. With κ3=1.0 (GRChombo), the full covariant Z coupling compensates for the strong damping.

Proven configurations (pick one)

Config 1: Match BAM/AthenaK/CarpetX (Z4c standard)

--kappa1 0.02 --kappa3 0.5 --covariant 0

Damping vanishes at puncture. Every Z4c code does this. Safest for puncture evolutions.

Config 2: Match GRChombo (covariant CCZ4)

--kappa1 0.1 --kappa3 1.0 --covariant 1

Constant damping, but κ3=1 provides full covariant Z coupling to balance it. Must use κ3=1 with covariant per Alic 2013.

6. Recommendation

Fix both the KO margin AND the CCZ4 formulation mismatch.

The KO ghost margin (Section 1) and the CCZ4 hybrid configuration (Section 5) are independent problems that compound at the finest AMR level. The recommended approach:

  1. KO fix: Option A (6th-order KO) or Option B (σ=0.1) — either gives margin or reduces amplification
  2. CCZ4 fix: Config 1 (BAM/AthenaK: non-covariant, κ1=0.02) or Config 2 (GRChombo: covariant, κ3=1.0)
  3. Gauge fix: η=2.0 (BAM calibrated) + cap position-dependent η at a reasonable bound

Option C (ghost=5) is architecturally expensive and no code uses it. Skip it.

Resolution (2026-04-06)

GRChombo route chosen — targeting multi-body simulations (25+ BH). GRChombo is the only code proven at that scale (arXiv:2505.01495).

Changes applied:

  1. Option A: 6th-order KO (IMPLEMENTED) — KO_ORDER macro decoupled from FD_ORDER. Default KO_ORDER=6 (7-point stencil, half-width 3). Ghost margin = 1 cell with GHOST=4. Legacy 8th-order available via make KO_ORDER=8.
  2. κ3 = 1.0 — covariant CCZ4 formulation (GRChombo match). With covariant_Z4=true (constant κ1), κ3=1.0 is the mathematically consistent choice per Alic 2012 (arXiv:1106.2254). The previous κ3=0.5 + covariant was an untested hybrid used by no production code.
  • σ = 0.5 — AthenaK default for 6th-order FD + 6th-order KO. GRChombo’s σ=1.0 works because their 6th-order KO is 2 orders above their 4th-order FD (only damps unresolved noise). With our 6th-order FD, KO operates at the same order as the truncation error — σ=1.0 is too aggressive and causes constraint growth at fine AMR levels. The Einstein Toolkit stability bound is σ < 2×CFL = 0.5. Ref: arXiv:2409.10383 (AthenaK).

    • Other parameters unchanged: κ1=0.1, η=1.0. All CPU tests pass (convergence order 5.8–6.3, threshold ≥4).
