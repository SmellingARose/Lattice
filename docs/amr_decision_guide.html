2. Fixed Block Size vs Variable-Dimension Boxes

Fixed 16³ blocks (oct-tree — Athena++, AthenaK, GR-Athena++)

  • Every block is identical in shape. GPU kernel dispatch is trivial — batch N identical blocks into one launch, every thread does the same work.
  • Load balancing is trivial because all work units are the same size.
  • Memory allocation is predictable: 25 fields × 3 blocks (CK45) × 24³ × 8 bytes = 8.3 MB/block.
  • Ghost overhead: 24³/16³ = 3.4x — 70% of per-block memory is ghosts. Significant but bounded.
  • Refinement granularity is coarser: if only one corner needs refinement, all 8 children are created. But 7 of 8 typically won't need further refinement, so waste is bounded.

Variable-dimension boxes (block-structured — GRChombo, Carpet, AMReX)

  • Berger-Rigoutsos algorithm clusters tagged cells into arbitrary rectangles (32×64×16, 128³, etc.). Lower ghost overhead (1.2x for 128³).
  • Variable sizes kill GPU batching — can't batch a 32³ and a 128³ box in the same kernel without complex padding.
  • The clustering itself costs 5–15% of runtime (arXiv:2112.10567). Oct-tree regridding costs 1–3%.
  • For N-body, rectangular bounding boxes include empty space between BHs. Fill efficiency degrades from ~80% at N=2 to ~60–70% at N=25. Oct-tree stays at ~95% regardless of N.
Bottom line: For N-body + GPU targets, fixed 16³ is the correct choice. The ghost overhead is the price for uniform batching and linear N-scaling.

Athena++: Stone et al. 2020, §3.1; AthenaK: Grete et al. 2024 (arXiv:2409.16053), §4.2

3. What mesh_t Does

mesh_t does not need to be identical to the old grid_t code path. The point is that a 1-block mesh should produce the same physics output as the old single-grid path, verified by re-running tests. No dual code path needed.

mesh_t is the top-level orchestrator. It replaces the single grid_t pointer in main(). Specifically:

  1. Owns all blocks — maintains the flat array of block_t pointers, indexed by block ID. Knows which blocks exist at each level.
  2. Manages the oct-tree — parent/child relationships, Morton indices, neighbor lookup. When a block is refined (split into 8 children), mesh_t allocates children, links them into the tree, and deallocates the parent's field data.
  3. Orchestrates the per-step workflow: 
    ghost_exchange(mesh)           // fill all ghost zones
for each leaf block:
    compute_rhs(block)          // physics, unchanged from single-grid
    apply_sommerfeld(block)     // only on domain boundary faces
for each leaf block:
    rk_update(block)            // field updates
enforce_algebraic(mesh)         // det(gambar)=1, tr(Abar)=0
  4. Drives regridding — every N_regrid steps, evaluates the refinement criterion on all leaf blocks, enforces the 2:1 constraint, and executes refine/coarsen operations.
  5. Provides level iteration — "for each block at level L" loops needed for ordered ghost exchange (coarsest first).
  6. Holds domain parameters — L, dx_base, N_root, max_level, and simulation parameters.
Think of mesh_t as the "world" object. It is what the RK time stepper calls instead of operating on a single grid.

4. Ghost Exchange Approaches

There are 4 levels of sophistication, not just one way:

LevelApproachSync barriersComplexityBest for
13-pass face-only (x, then y, then z)2~300 linesCPU dev
2Direct 26-neighbor (1 parallel pass)0~600 linesGPU
3Communication-overlapped (compute interior while exchanging)0~800 linesMPI clusters
4On-device (all on GPU, no host round-trip)0~600 linesSingle GPU

How 3-pass works

Ghost zones have three region types: face ghosts (6 slabs), edge ghosts (12 columns), and corner ghosts (8 cubes). The 3-pass approach exchanges x-faces first. The y-pass then copies data including the x-ghost data that's now present, filling xy-edge regions transitively. The z-pass fills xyz-corners the same way. Correct and simple, but 2 serial barriers.

On CPU, the barriers cost microseconds (negligible). On GPU, each barrier costs ~0.5–1 ms (kernel completion + relaunch). For many blocks, 2 barriers = 5–10% of a timestep.

Start with Level 1 (3-pass face-only). Upgrade to Level 2 or 4 for GPU in Stage 6. Skip Level 3 (MPI optimization we don't need).

Athena++ (Level 1): Stone et al. 2020, §4.2; AthenaK (Level 2+4): Grete et al. 2024, §4.1

5. Higher-Order Prolongation for N-Body

What production NR codes use

CodeProlongation orderNotes
BAM5th-order LagrangeBrugmann et al. 2008, §3.3
GRChombo4th-orderAndrade et al. 2021, §4.3
Carpet (Einstein Toolkit)3rd-order default, up to 5thConfigurable
GR-Athena++2nd-order (minmod)Vertex-centered compensates
Dendro-GRWavelet-based (inherently high-order)Different paradigm

Why higher order matters more for chaotic N-body

  • Multiple BHs = more refinement boundaries. More boundaries = more surfaces where prolongation error enters the solution.
  • Chaotic trajectories = BHs cross boundaries frequently. Each crossing generates prolongation error.
  • Accumulated error over long integrations shifts trajectories. In chaotic systems, small errors grow exponentially. 2nd-order prolongation error (~dx²) compounds much faster than 4th-order (~dx⁴).

Risk of higher-order near punctures

Near punctures, chi approaches zero with very steep gradients. High-order polynomial interpolation of such functions can produce Gibbs-like ringing. This is why minmod was originally chosen — the limiter clamps interpolation to avoid overshooting.

However, with CAKO in place, the risk is substantially mitigated. CAKO drives KO dissipation to zero near punctures (where chi is small), so any ringing from prolongation is not amplified. The combination of 4th-order Lagrange + CAKO hasn't been published, but the physics reasoning is sound: CAKO prevents dissipation from interacting badly with the interpolation oscillations.

Start with minmod to get AMR running. Upgrade to 4th-order Lagrange as a near-term priority. Don't go above 5th — diminishing returns vs wider stencil requirements.

6. Restriction (Fine → Coarse)

Restriction is conceptually the simplest AMR operation: average 8 fine cells into 1 coarse cell.

With a 2:1 refinement ratio, each coarse cell overlaps exactly 2³ = 8 fine cells. Restriction computes:

U_coarse(I,J,K) = (1/8) * sum over the 8 fine cells that overlap this coarse cell

Why it's needed

Without restriction, the coarse grid drifts from reality. Two problems:

  1. Stale ghost data: When fine-block ghost zones need coarse data (via prolongation), they'd get outdated values. Errors propagate into the fine-grid interior.
  2. Discontinuity on coarsening: When you coarsen a region (BH moved away), the revealed coarse data would be discontinuous with what was just there.

Restriction keeps the coarse grid "up to date" by injecting the fine-grid solution into it. Conservative by construction — the sum is preserved. ~100 lines of C.

7. Chi-Gradient Refinement Criterion

Essential. Without it, you cannot do dynamic AMR for N-body.

Without a refinement criterion, you have two inferior options:

  • No criterion → uniform grid (can't resolve BHs at practical memory sizes)
  • Static refinement → must know BH positions in advance (impossible for chaotic N-body)

What chi-gradient gives you automatically

Chi (the conformal factor) goes to zero at each puncture. Its gradient |∇χ| is steep near each BH and nearly zero in the wave zone. By flagging blocks where |∇χ| × dx exceeds a threshold, you automatically:

  1. Detect every BH regardless of N, without a puncture tracker
  2. Track moving BHs — as a BH enters a new block, chi gradient spikes → refinement
  3. Give more levels to smaller BHs — steeper gradients at the same distance → more refinement
  4. Handle mergers — remnant chi profile differs from two separate BHs, pattern adjusts
  5. Handle ejections — flung-out BHs tracked across the domain

No other simple criterion gives all five for free.

Sufficient for spin and charge?

Spin: yes (Bowen-York puncture structure is identical — chi still goes to zero). Charge (Phase 2): chi still correctly identifies puncture locations. EM fields are largest where chi is smallest. Add supplementary |∇E| + |∇B| criteria only if EM fields have structure independent of BH positions.

GRChombo: Andrade et al. 2021, §5.1; arXiv:2312.05438 (refinement strategy comparison)

8. CAKO: Why It Doesn't Destroy Wave Data

The concern: CAKO scales KO dissipation by chi. In the wave zone, chi ≈ 1, so CAKO applies full dissipation there. Won't this destroy the physical gravitational wave signal?

No. Here's why.

KO dissipation is a high-pass filter

KO dissipation adds a term proportional to the (2p+2)th derivative. For 6th-order KO, this is the 8th derivative. It acts preferentially on high-frequency modes near the Nyquist frequency (wavelength ~ 2·dx).

Physical gravitational waves have wavelengths λGW ~ 10–100M. At the extraction radius (r ~ 50–100M), grid spacing is dx ~ 1–2M. So GWs span 5–100 grid points — they are smooth, well-resolved. The KO correction on them is O(dx&sup8;/λ&sup8;) ~ O(10⁻&sup8;). Negligible.

What CAKO actually targets

The noise from refinement boundary interpolation has wavelengths of 2–4 dx (high-frequency interpolation artifacts). The KO operator discriminates between GWs (5–100 dx) and this noise (2–4 dx) by many orders of magnitude because it's an 8th-order high-pass filter.

Empirical proof

Etienne 2024 (arXiv:2404.01137) reports that with CAKO, extracted Psi4 shows improved accuracy: 4.3x noise reduction in the dominant GW mode, higher modes (l≥4) becoming detectable above the noise floor. If CAKO were destroying wave data, the waveform would get worse, not better.

CAKO destroys high-frequency interpolation noise. It does not destroy gravitational waves. Same physics principle as any low-pass/high-pass filter — remove noise above the signal band.

9. Dynamic Regridding Frequency

Don't check every timestep. Three reasons:

  1. Cost: Each regrid costs 1–3% of a timestep. Every step = 1–3% overhead. Every 10 steps = 0.1–0.3%.
  2. Noise injection: Each new fine block gets prolongated (interpolated) data, injecting O(dxp) error. More frequent regridding = more noise.
  3. Block churn: Borderline blocks oscillate between refined/coarsened if checked too often.

How fast do BHs actually move on the grid?

A BH at coordinate velocity v ~ 0.01–0.1c moves ~0.001–0.01 cells per finest-level timestep (since dt ~ CFL × dx). That's ~1 cell per ~400 finest-level timesteps. At the coarsest level relevant for regridding, a BH moves roughly 1 coarse cell per ~10–50 coarse timesteps.

Checking every 10 steps is more than fast enough to keep up with any BH velocity.

Use N_regrid = 10. For chaotic N-body, reduce to 5 if BHs outrun their refinement regions. Going below 5 is unlikely to help. Hysteresis thresholds (chi_refine vs chi_coarsen, with chi_coarsen << chi_refine) matter more than frequency for preventing block churn.

GRChombo: ~10 steps; Athena++: configurable, typically 10–20; BAM: fixed mesh (no dynamic regridding)

10. Time Subcycling

The problem

Each refinement level has dxL = dx0 / 2L. CFL requires dt ∝ dx. Without subcycling, all levels share dt = CFL × dxfinest — coarse levels take unnecessarily tiny steps.

The three options

Option A: Global dt (no subcycling)

All levels advance with dt = CFL × dxfinest. One loop over all blocks, same dt for everyone.

  • Extremely simple. No inter-level synchronization.
  • GPU-friendly — all blocks advance together = perfect batching.
  • Coarse blocks do 2L_max more work than needed. With 6 levels, that's 32x per coarse block.
  • But: for N-body, most blocks are at fine levels (near BHs). If 10 BHs produce 400 fine blocks and only 50 coarse blocks, the waste is ~12%, not 32x.

Used by: AthenaK (GPU), Dendro-GR

Option B: 2:1 subcycling (Berger-Oliger)

Level L+1 takes 2 steps for every 1 step at level L. Recursive: advance fine, restrict to coarse, advance coarse.

  • Optimal efficiency — no wasted steps. 2–4x speedup (arXiv:2503.09629).
  • Complex recursive scheduling (~600 lines). Inter-level ghost timing is critical.
  • Needs dense output for 4th-order temporal accuracy at boundaries.

Used by: GRChombo, Carpet, BAM, CarpetX

Option C: Level-by-level with synchronization

Advance all blocks at coarsest level, then next finer (2 steps), then next (4 steps), etc. Restrict after each level completes.

  • Simpler scheduling than recursive. Better GPU batching potential.
  • Slightly less accurate at inter-level boundaries than recursive.
Start with Option A (global dt). For N-body with many BHs, most blocks are fine-level anyway, so waste is small. Add subcycling later only if profiling shows coarse-level waste is a real bottleneck.

11. Making MeshBlockPack Simple

The goal: avoid launching one GPU kernel per block. Minimum viable approach:

Step 1: One contiguous buffer

// Instead of each block having separately-allocated fields[25] arrays:
double *pack = aligned_alloc(4096, N_fields * N_blocks * Ntotal * sizeof(double));
// Layout: pack[field * N_blocks * Ntotal + block_idx * Ntotal + linear_idx]

Step 2: One kernel launch

// Instead of N_blocks separate kernel launches:
#pragma omp target teams distribute parallel for
for (int bidx = 0; bidx < N_blocks * Ntotal; bidx++) {
    int b = bidx / Ntotal;
    int idx = bidx % Ntotal;
    ccz4_rhs_point_packed(rhs_pack, src_pack, b, idx, ...);
}

Step 3: Adapted field access

FD macros get an extra block-index parameter: pack[f * N_blocks * Ntotal + b * Ntotal + IDX(i,j,k)]. Abstract with a macro or inline function.

What to skip initially

  • On-device ghost exchange (just do it on CPU and transfer updated ghost zones)
  • Pack/unpack — keep the packed layout permanently
  • Variable packing (subset of fields) — pack all 25
  • Multi-level packing — pack all leaf blocks regardless of level
Going from 500 separate launches to 1 eliminates ~3 ms launch overhead per RK substep. Combined with better GPU occupancy from more threads per launch, expect 6–30% speedup from batching alone.

AthenaK: Grete et al. 2024, §4.2, Fig. 5

13. SSL for N-Body Chaotic Simulations

The SSL term is per-point, not per-puncture:

dt(α) += -W · h · exp(-t²/(2σ_t²)) · (α - W)
// W = chi, h = 0.6M, σ_t = 20M

Why it should work for N-body

  • Near each puncture: chi → 0 so W → 0, SSL term vanishes. Doesn't fight lapse collapse.
  • Between punctures: drives α toward 1, smoothing each gauge pulse at its source independently.
  • With N punctures generating N simultaneous pulses, SSL dampens each before they interact — better than without SSL.
  • The parameters reference total mass M (which sets global dynamics timescale), appropriate regardless of N.
  • The Gaussian makes SSL negligible after t ~ 60M, completely transparent after t ~ 170M. Tiny fraction of a multi-thousand-M simulation.
Caveat: Only validated for N=2 (Etienne 2024, 100+ BBH configurations). No published test for N>2. Physics reasoning says it extends, but verify with a 3-body test. If many closely-spaced punctures create a stronger combined gauge transient, σ_t might need increase.

arXiv:2404.01137 (Etienne 2024), §II.C

14. Dense Output

The problem it solves

When subcycling, fine and coarse levels are at different times. The fine level needs coarse ghost data at time t + dtfine, but the coarse level only has data at t and t + dtcoarse.

Without dense output: linearly interpolate in time. Only 2nd-order accurate, even if the RK integrator is 4th-order.

What dense output actually is

It uses the intermediate stages of the Runge-Kutta method (k1, k2, k3, k4 computed during the coarse step) to construct a continuous time interpolation polynomial:

U(t + θ · dt) = U(t) + dt · Σ b_i(θ) · k_i

where bi(θ) are polynomials derived from the RK Butcher tableau. This gives 4th-order accurate data at any intermediate time, not just at the endpoints.

Cost

Must store all RK stages per block. For CK45 (5 stages), that's 5 extra field-sized arrays per block — significant memory increase. The interpolation itself is cheap (5 multiplies and adds per point).

Is it worth it?

CarpetX implements this and achieves 4th-order convergence in time at refinement boundaries (vs 2nd-order with linear interpolation). But: spatial interpolation error (prolongation) dominates temporal interpolation error in practice. BAM and GRChombo operate at 3rd-order temporal accuracy at boundaries and produce science-grade waveforms.

Defer indefinitely. Only relevant with subcycling (irrelevant with global dt). Even with subcycling, spatial error dominates. Build only if convergence tests specifically show temporal error dominating at refinement boundaries.

CarpetX: arXiv:2503.09629; BAM: Brugmann et al. 2008

15. Per-Field Dissipation Strength

What it does

Instead of one σ for all 25 fields, use different values per field group:

  • Gauge variables (lapse, shift[3], B[3] — 7 fields): σ = 0.99 (aggressive)
  • Physical variables (chi, h[6], K, A[6], Γ[3], Θ — 18 fields): σ = 0.3 (gentle)

Why

Gauge variables are fundamentally different from physical variables:

  1. Characteristic speeds: 1+log gauge has superluminal characteristic speeds (√2·c). Faster propagation = more noise at refinement boundaries.
  2. Gauge freedom: Lapse and shift are coordinate choices, not physics. Dissipating them aggressively doesn't destroy physical observables.
  3. Noise amplitudes: Gauge variables accumulate the largest high-frequency noise in practice.

Risk: Over-dissipating Γi (conformal connections) could suppress constraint damping. Etienne's σ = 0.3 for Γi is conservative and avoids this.

Good idea. Trivial implementation (~20 lines: sigma scalar → per-field array). Defer until CAKO is working, then add as an easy enhancement. Use Etienne's values as a starting point.

arXiv:2404.01137 (Etienne 2024), §II.A, Table 1

16. Direct Edge & Corner Ghost Exchange

Face-only (3-pass)

Exchange x-faces, then y-faces, then z-faces. Edges and corners filled transitively across passes. 2 sync barriers. ~300 lines. Only need to identify 6 face-neighbors per block.

Direct 26-neighbor (1-pass)

Fill all 6 face + 12 edge + 8 corner neighbors in one parallel pass. 0 sync barriers. ~600 lines. Must identify all 26 neighbors per block. Edge/corner neighbors across refinement levels require special handling.

17. Truncation Error Criterion for Spin + Charge

For vacuum BHs (Phase 1, with or without spin): No.

Chi-gradient produces nearly identical refinement patterns to truncation error for vacuum BHs. Confirmed by arXiv:2312.05438, which compared the two for BBH and found they produce the same block distribution. Truncation error is 2x more expensive (requires computing RHS on a coarsened grid at each regrid) for no benefit.

For charged BHs (Phase 2, Einstein-Maxwell): Still no.

Chi still goes to zero at charged punctures. EM fields (Ei, Bi) are largest where chi is smallest. Chi-gradient will correctly identify where charged BHs are.

If EM fields have structure independent of BH positions (e.g., EM radiation with wavelengths shorter than GWs), add supplementary criteria: |∇E| + |∇B|. This is still far cheaper than full truncation error estimation.

Skip truncation error entirely. Use chi-gradient for BH tracking. Add field-specific criteria (|∇E|+|∇B|) for Phase 2 if needed. Full truncation error is 2x cost for marginal benefit.

arXiv:2312.05438 (2024), §4, Fig. 8

18. Vertex-Centered Discretization

Skip. Confirmed.
  1. Architectural cost: The entire codebase (grid layout, FD stencils, initial data, diagnostics, boundary conditions, all tests) assumes cell-centered. Switching is a rewrite, not a refactor.
  2. The problem it solves is addressed by other means: Vertex-centered reduces interpolation error at refinement boundaries because coarse/fine grids share coincident vertices. CAKO + CAHD + SSL achieve the same noise reduction without changing the discretization.
  3. Cell-centered is the majority choice: GRChombo, BAM, Carpet/CarpetX, Dendro-GR, NRPy+ all use cell-centered and produce science-grade waveforms.
  4. GR-Athena++ chose vertex-centered partly because Athena++ was already vertex-centered for MHD divergence-free reasons, not for NR-specific benefits.

19. Flux Correction / Refluxing

Phase 1 (vacuum): Skip.

CCZ4 is not in conservative form. The evolved variables (hij, K, Aij, etc.) don't have a conservation interpretation. Constraint damping (kappa1/kappa2/Theta) handles boundary violations through a different mechanism — active correction based on the constraint equations, not passive flux matching.

BAM implemented flux correction for BSSN and found it helped only for the principal (advection) part, not source terms. Marginal improvement compared to CAKO/CAHD. GR-Athena++ and Dendro-GR don't use flux correction. GRChombo inherits refluxing from Chombo but notes it's "not essential for vacuum spacetimes."

Phase 2 (Einstein-Maxwell): Maybe.

Maxwell's equations are naturally conservative. Electric charge Q must be preserved — div(E) = ρe. At refinement boundaries, E/B fields evolved independently then synchronized via restriction/prolongation could violate charge conservation.

Skip for Phase 1. For Phase 2, evaluate whether charge conservation violations at refinement boundaries are problematic. If yes, implement flux correction for Ei and Bi only (not CCZ4 variables) — much smaller scope.

20. Buffer Zones vs CAKO/CAHD/SSL

CAKO + CAHD + SSL largely replace buffer zones.

Buffer zones are the brute-force approach: refine extra blocks around each refined region to push the boundary away from the physics. GRChombo uses 3-block buffers and still reports significant boundary noise (arXiv:2112.10567). Buffers alone are insufficient.

CAKO + CAHD + SSL attack the cause of the noise:

  • CAKO: suppresses noise generation (spatially adaptive dissipation)
  • CAHD: accelerates noise absorption on coarse grids
  • SSL: prevents initial gauge pulse from generating noise at boundaries

Together: 2–5 OOM noise reduction at zero additional memory. Buffer zones roughly double the number of blocks at each level for much less noise reduction.

Practical approach

  1. Start without buffer zones. Implement CAKO + CAHD + SSL from Stage 3.
  2. Monitor constraint norms at refinement boundaries.
  3. If violations are unacceptable despite CAKO/CAHD/SSL, add a 1-block buffer (not 3) and re-test.
  4. The 2:1 level constraint already provides implicit buffering (at least one intermediate block between any two levels).
Build without buffer zones. CAKO/CAHD/SSL are the modern replacement. Add minimal buffer only if empirical tests demand it.

arXiv:2404.01137 (Etienne 2024), §I; GRChombo: arXiv:2112.10567
