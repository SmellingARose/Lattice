0. Correctness Bugs (all fixed)

0th-order restriction in parent sync FIXED

restrict_level_to_parents() used simple 2×2×2 averaging (0th-order) to populate non-leaf parent data. Fine-level RHS saw O(h2) ghost data at coarse–fine boundaries.

Fix (commit 32290ab): restrict_cell() moved to restriction.h as static inline, called from restrict_level_to_parents(). Now uses the same 6th-order Lagrange stencil as all other restriction paths.

CK45 subcycling never saves k1 FIXED

The CK45 subcycling path never called save_k1_from_pack. rhs_old stayed all-zeros, degrading quartic temporal interpolation.

Fix (commit 32290ab): Added if (s == 0) save_k1_from_pack(pack, m->blocks); in the CK45 subcycling stage loop.

enforce_algebraic_block uses slow path FIXED

refine.c had a copy of enforce_algebraic using 1.0 / cbrt(det) (3–5x slower) with a divergent if (det > 0.0) guard that could skip enforcement entirely.

Fix: fast_inv_cbrt() moved to tensor_utils.h (commit 32290ab). enforce_algebraic_block() in refine.c updated to use fast_inv_cbrt(det) unconditionally, matching rk4.c.

Known Issues (discovered during Tier 0 work)

AMR dynamic-regrid produces NaN FIXED

ghost_fill_from_coarser() had an ordering bug: restrict → exchange → prolongate ran per block in a single loop, so block B could read neighbor C's coarse_buf before C had been restricted (stale/zero data → NaN).

Fix: Split into two passes — Pass 1 restricts all fine blocks, Pass 2 does exchange + prolongate. Removed has_coarser_leaves workaround from step_level(). Test 2 now passes with classic RK4 (Ham L2 = 2.9e-03).

Classic RK4 packed mesh divergence INVESTIGATE

test_amr_evolve Test 1: classic RK4 packed mesh stepper produces 10x higher constraint violations than CK45 packed stepper (ratio 11.87 vs expected ~1.0). Pre-existing — classic_rk4_step_mesh_packed() was never tested before (tests always used CK45). Single-grid classic RK4 works correctly.

Likely cause: Bug in classic_rk4_step_mesh_packed() stage ordering or buffer management. CK45 packed path (ck45_step_mesh_packed()) works correctly as the reference.

1. Position-Dependent Eta

Most critical change for N-body. A global eta that works for M=5 is wrong for M=0.5. Use eta(x) = eta_0 / sqrt(chi) (GRChombo 25-BH convention, arXiv:2505.01495). Alternative: eta_0 / alpha, similar but gauge-dependent.

Implementation 1 line change
// ccz4_rhs.c
double W = sqrt(fmax(chi, 1e-10));
double eta_local = p->gauge.eta / W;
rhs_B[ii] = ... + rhs_Gamma[ii] - eta_local * B[ii];

2. CCZ3 Formulation

Standard CCZ4's kappa1 damping causes momentum constraint violations to accumulate, producing instability at ~103–104 M (arXiv:2501.01055). Removing the damping lets violations propagate out through Sommerfeld BCs instead.

3. Checkpoint/Restart

Raw binary + text header + CRC32 Zero dependencies
  • Header: ASCII magic, key-value metadata (N, L, step, time, params), endianness marker
  • Data: Interior points only (ghosts reconstructed). Sequential per field, per block for AMR.
  • Footer: CRC32 checksum. Ring buffer of 2 files.
  • Performance: N=128, 31 fields: ~512 MB. On NVMe at 3 GB/s: 0.17 sec.
  • Async: fork() for CPU (copy-on-write), pthread + double buffer for GPU.

4. Waveform Extraction

StepWhat
1Compute Psi4 on grid
2Interpolate onto spheres at r = {50, 75, 100, 150, 200} M
3Decompose into (l,m) modes via s=−2 spherical harmonics
4Output r·Psi4lm(t) time series
5FFI to strain + 1/r extrapolation (Python post-processing)

Two extraction approaches: fixed-radius + extrapolation (standard, <1% accuracy for BBH) and CCE via SpECTRE worldtube (gauge-invariant at J+, captures GW memory, needed for LISA/3G). CCE worldtube at r~25M sits in the AMR-refined region, sidestepping wave zone resolution issues. ~300 LOC C for worldtube output.

The extraction sphere must not cross AMR refinement boundaries. Constrain regridding so the sphere's bounding box stays within one level (~20 lines in criterion.c).

3D output: XDMF + raw binary for ParaView/VisIt. Each AMR block is a <Grid> element. ~200 lines of C.

6. Performance Optimizations

Quick Wins

LTO (-flto) DONE

Added -flto to CFLAGS_OPT in the Makefile (CPU only; GPU LTO broken in GCC 15). Enables cross-TU inlining of ccz4_rhs_point through the function pointer in backend_cpu.c. Commit 32290ab.

__restrict__ on RHS pointers DONE

Added __restrict__ to ccz4_rhs_point signature and backend dispatch functions. GPU-safe. Commit 32290ab.

OpenMP-parallelize ghost exchange + Sommerfeld DONE

Both packed ghost exchange and Sommerfeld BCs now use #pragma omp parallel for schedule(dynamic). Commit 32290ab.

Conditional EM allocation 19% memory

The 6 EM fields are always allocated even when --em is off. Saves ~970 MB at N=256, ~4.5 GB for 200-block AMR. ~20 lines.

Compile-time EM dispatch 4–5%

Build two object files: backend_cpu_ccz4.o (NUM_ACTIVE_FIELDS=25) and backend_cpu_em.o (31). Eliminates all runtime EM branches, wasted dissipation, wasted allocation. Subsumes the "hoist em_enabled" and "skip EM in dissipation" items. AthenaK does this via C++ templates. ~20 LOC Makefile change.

CPU

Fused d1/d2 stencil 15–20% CPU, 5–10% GPU

11 fields need both d1 and d2 per direction. Currently loads the same 7 stencil points twice. A fused fd_d1_d2() halves the load count: 33×3 = 99 redundant load sequences eliminated. ~50 lines.

Triple-fused d1/d2/advection stencil 2–3% additional

Extension of d1/d2 fusion. The 4 scalar fields needing all three derivatives per direction (chi, K, Theta, lapse) share overlapping stencil points {-4..+4}. Currently 21 loads per field per direction; fused: 9. Saves 144 loads/point. ~40 LOC.

Common subexpression elimination 10–20% FLOPs

chris.ULL[m][kk][ll] is reused across Ricci, Gamma RHS, and A_ij RHS. Manual extraction of Christoffel products and metric contractions. NRPy+ reports ~21% instruction reduction via SymPy CSE (arXiv:2501.14030). ~50 lines.

Exploit Ricci symmetry ~1%

ccz4_rhs.c:203-238: Ricci is symmetric (R_ij = R_ji) but FOR2(ii,jj) computes all 9 entries (243 Christoffel FMAs). Compute upper triangle only: 162 unique FMAs. ~15 lines.

Symmetric tensor raise 2–3%

raise_all_2() in tensor_utils.h computes all 9 entries of Aij but only 6 are unique. 54 FMAs → 36. ~20 lines.

Derivative precomputation for mixed d2 30–50% fewer loads

fd_d2_mixed() uses a 7×7 = 49-point stencil. Store d1 in scratch, compute mixed d2 as 1D stencils: 7 loads instead of 49 per mixed pair. 33 instances. Requires scratch storage.

Flatten per-grid RK4 update DONE

Flattened to single OMP region over NUM_FIELDS * npoints. Eliminates 31 separate OpenMP dispatch cycles. Commit 32290ab.

Fast-path pow(lapse, 1.0) DONE

Default lapse_power=1.0 now uses identity fast path, avoiding 50–100 cycle pow() call. Commit 32290ab.

Hoist advection sign check 5–8% GPU

fd_adv() branches on vel > 0.0 at every call. Same shift direction for all ~22 field advections per direction = 66 redundant branches. Add branchless fd_adv_pos()/fd_adv_neg(), select once per direction. ~25 lines.

Fuse Hamiltonian + momentum constraints 40–45% diagnostics

constraints.c:82 and constraints.c:254 independently compute derivatives, inverse metric, and Christoffel symbols. Share intermediates when both are evaluated. ~80 LOC. Diagnostics only, not RHS hot path.

Unroll Levi-Civita curl in Maxwell RHS 5–8% Maxwell

maxwell_rhs.c:265-273: FOR4(a,b,c,d_idx) = 81 iterations per component but Levi-Civita is nonzero for only 6 of 27 triplets. 78% wasted. Unroll explicitly. ~30 LOC.

Interior/boundary RHS split 10–20% AMR

Compute interior RHS while ghost exchange runs concurrently. Used by GR-Athena++, SpECTRE, ExaGRyPE. ~150 lines.

GPU

Persistent per-level packs 15–30% CPU, eliminates 95% GPU PCIe

Biggest AMR performance issue. With 4-level subcycling, packs are rebuilt 2L−1 = 15 times per coarse step. Each rebuild: malloc×4 + calloc×7 + memcpy load + GPU map + 5 CK45 stages + GPU unmap + memcpy store + free. For 100 blocks at N_block=32: ~48 GB memcpy/step CPU, ~142 GB PCIe/step GPU. Fix: one pack per level, rebuild metadata only after regrid. ~200 lines.

Device-side ghost exchange 2–5x GPU overall

The single largest GPU bottleneck. backend_gpu.c:879-910 syncs entire pack to host, runs all 5 ghost phases on CPU, syncs back. ~8 GB/step PCIe. AthenaK does all ghost exchange on-device. ~300 lines.

Hoist GPU grid_t construction DONE

GPU grid_t construction hoisted out of per-thread scope. Commit 32290ab.

Kernel splitting for occupancy 20–40% GPU

RHS kernel uses ~400 registers = ~25% occupancy on A100. Split into Phase A (derivatives, ~200 registers) and Phase B (Ricci + assembly, ~200 registers). ~400 lines.

GPU kernel occupancy tuning 5–15% GPU

backend_gpu.c:44,198,268,349: All GPU kernels lack num_teams / thread_limit clauses. The RHS kernel should use thread_limit(64) to avoid register spill; bandwidth-limited kernels (CK45 update, zero) should use thread_limit(256). ~5 lines per kernel, requires profiling.

Sommerfeld switch/case → array lookup Warp divergence fix

sommerfeld.c:24-34: asymptotic_value() switch with 31 cases causes warp divergence on GPU. Replace with static const double asym_values[NUM_FIELDS]. ~5 lines.

enforce_algebraic on GPU ~130 ms/step

rk4.c:649-659: After backend_unmap_pack(), enforce runs on CPU requiring full D2H. It's per-point (no neighbor access) — trivially a GPU kernel. Port fast_inv_cbrt, compute_det_sym, etc. to omp declare target. ~60 LOC.

save_k1 on device ~130 ms/step

rk4.c:754-768: save_k1_from_pack() copies entire RHS buffer (~1.58 GB) to host mid-step. Store k1 in a dedicated device buffer instead. ~30 LOC.

Optimal block size 2–30x GPU

N_block=32 minimum, 64 optimal for GPU (Parthenon-VIBE, arXiv:2509.19701). Already configurable. Zero code changes.

Reorder d2 for instruction cache 10–20% GPU

Sort d2[min(i,j)][max(i,j)] to maximize instruction reuse within 32 KB instruction cache. Low effort.

Direct ghost-region iteration 2x prolongation, 40x fewer Sommerfeld threads

ghost_exchange.c:462-536, backend_gpu.c:253-330: Currently iterate over all Nt3 points and skip interiors via branch. For N_block=32: 51% skipped. Replace with 6 face + 12 edge + 8 corner loops. For Sommerfeld GPU: build boundary-cell index list. ~160 lines total.

AMR

Eliminate refinement memory spike ~2.3 GB saved

refine.c:34-72: Allocates temporary fine grid at 2x parent resolution (~282 MB per child, ×8 = ~2.3 GB peak). Prolongate directly into each child using octant-aware stencil. ~50 LOC.

Pre-allocate ghost exchange scratch buffers Eliminates malloc/free

ghost_exchange.c:611-638: Allocates/frees ~15.9 MB interpolation buffer per coarse neighbor per fine block. 50+ malloc/free cycles per ghost fill. Pre-allocate thread-local scratch. ~15 LOC.

Hash table for neighbor lookup O(n) regrid

mesh.c:367-465: O(n2) linear scan for each block × 26 neighbors × max_level. For 1000 blocks: ~100M comparisons per regrid. Hash (level, lx1, lx2, lx3) → block_id. ~40 LOC.

Pre-compute restriction/prolongation weights DONE

232-entry weight product tables pre-computed as static const. Bit-exact verified against runtime computation via tools/verify_weights.c. Commit 32290ab.

Fix subcycling temporal fraction drift Correctness

rk4.c:1037: floor(t_start / dt_coarse) * dt_coarse accumulates rounding errors over 104+ steps. Pass frac directly from recursive call site. ~10 LOC.

Memory

Already sound: Classic RK4 (default) uses 4 memory blocks; CK45 uses 3 (25% less memory but 5 stages vs 4). No malloc/free inside time-stepping loops. Page-alignment waste is <4 KB per block. Ghost width=4 is required for 6th-order FD + 8th-order KO (unavoidable). At N_block=16: 4.1x ghost overhead; N_block=32: 1.95x; N_block=64: 1.51x.

7. Mathematical Methods

Dense output for temporal interpolation HIGH IMPACT

Current quartic interpolation at coarse–fine boundaries stores 5 quantities per point. RK4 dense output achieves 4th-order temporal accuracy using the 4 stage vectors + pre-step state:

y(t_n + θ·h) = y_n + h·[b1(θ)·k1 + b2(θ)·k2 + b3(θ)·k3 + b4(θ)·k4]
b1 = θ - 3θ2/2 + 2θ3/3
b2 = b3 = θ2 - 2θ3/3
b4 = -θ2/2 + 2θ3/3

CarpetX (arXiv:2503.09629) uses this for 4th-order convergence at AMR boundaries. ~200 lines.

Note: Works naturally with classic RK4 (now the default). CK45's 2N storage overwrites stage vectors, so subcycling steps would need classic RK4 anyway.
Adaptive constraint damping (dynamic kappa1) Better than fixed CCZ4

Instead of fixed kappa1=0.1, adapt based on local constraint magnitude: kappa1_local = kappa1_base * f(Ham, Mom). Strong early damping during junk radiation, weak late for long-term stability. Middle ground between CCZ4 (unstable ~103 M) and CCZ3 (no damping). ~20 LOC. Ref: arXiv:2409.01939.

Taylor-based AMR prolongation ExaHyPE approach

Instead of tensor-product Lagrange, use Taylor expansion around nearest cell center: compute local derivatives on source grid, evaluate polynomial at target cells. ExaHyPE demonstrates reduced accumulated errors near AMR boundaries. ~200 LOC. Ref: arXiv:2504.15814.

Richardson extrapolation refinement criteria 10–30% fewer blocks

Instead of chi-gradient heuristic (criterion.c), estimate local truncation error by comparing leaf solution against coarser parent level. Physics-agnostic, catches truncation error in any field. Coarse solution already available from AMR hierarchy. ~150 LOC. Ref: arXiv:2404.16648.

Optimized-stability 2N RK methods 20–50% fewer steps

Niegemann et al. (2012): 2N methods with 8–14 stages optimized for max CFL. 1.5–2x larger stable timestep. Ketcheson (2010): 4th order in 4 stages (vs CK45's 5). Swapping coefficients is trivial.

P-ERK (Paired Explicit Runge-Kutta) 2–5x on AMR

Different blocks use different RK stage counts by local stiffness. 1.5–5x for 4–6 AMR levels (arXiv:2403.05144). Very high complexity.

IMEX for constraint damping Larger dt with strong kappa1

Treat stiff damping sources (kappa1·Theta, kappa1·Z_i) implicitly, spatial derivatives explicitly. The implicit part is purely local (no spatial derivatives) — just point-wise algebraic inversion. Allows larger kappa1 without reducing dt. ~300 LOC. Ref: arXiv:2411.23015.

Hyperbolic relaxation for initial data 2–4x GPU speedup for ID

Transform elliptic Hamiltonian constraint into a damped hyperbolic PDE and evolve to steady state. Maps naturally onto GPU kernels (same FD infrastructure). No tridiagonal solves, no colored sweeps. ~500 LOC. Ref: arXiv:2501.14030 (NRPyEllipticGPU), arXiv:2111.02424.

AMR-enabled constraint solver 5–10x for N-body

Use AMR during the constraint solve itself, concentrating resolution near punctures. For N=10+ widely-separated punctures, most of the domain is flat. ~500+ LOC. Ref: arXiv:2501.13046 (GRTresna).

Mixed-order stencils near punctures 10–20% on fine levels

4th-order FD on finest levels (solution is C2–C4), 6th-order elsewhere. Both in finite_diff.h. Per-block runtime selection needs two RHS versions.

KO dissipation stage reduction Few %

Apply KO at 1 RK stage instead of all 5. Low effort but stability risk near punctures.

Why 6th-Order FD

6th order is the production standard among FD-based NR codes (AthenaK, GR-Athena++, BAM). We upgraded in February 2026 with zero infrastructure changes — GHOST_WIDTH=4 already supported 6th-order FD + 8th-order KO. The key numbers:

  • 170x cheaper than 4th order at ε=10−6 (despite 1.63x more FLOPs/point, you need far fewer grid points)
  • N=91 at 6th order matches N=256 at 4th order for the same accuracy
  • Prolongation/restriction matched at 6th order — no operator mismatch at AMR boundaries

Going to 8th order is not worth it: requires ghost=5 (breaking change to grid, AMR, boundaries), puncture solutions are C2–C4 (saturates beyond 6th), and RK4 time error O(h4) dominates.
