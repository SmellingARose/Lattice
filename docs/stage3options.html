1. Position-Dependent Eta

Most critical change for N-body. A global eta that works for M=5 is wrong for M=0.5. Use eta(x) = eta_0 / sqrt(chi) (GRChombo 25-BH convention, arXiv:2505.01495). Alternative: eta_0 / alpha, similar but gauge-dependent.

Implementation 1 line change
// ccz4_rhs.c
double W = sqrt(fmax(chi, 1e-10));
double eta_local = p->gauge.eta / W;
rhs_B[ii] = ... + rhs_Gamma[ii] - eta_local * B[ii];

2. CCZ3 Formulation

Standard CCZ4's kappa1 damping causes momentum constraint violations to accumulate, producing instability at ~103–104 M (arXiv:2501.01055). Removing the damping lets violations propagate out through Sommerfeld BCs instead.

AspectCCZ4 (current)CCZ4′CCZ3
Momentum dampingkappa1 * Z_iNoneNone
Long-term stability~103–104 M105 M105 M
Evolved fields252524 (no Theta)
Implementation
// CCZ4′: delete this line from the Gamma equation
rhs_Gamma[i] += ... - 2.0 * kappa1_times_lapse * Z_over_chi[i];  // DELETE

// CCZ3: also set Theta=0, skip rhs_Theta, "K - 2*Theta" becomes "K"

Add --formulation ccz4|ccz4p|ccz3 runtime flag. Synergy with 6th-order FD: fewer truncation-error-generated violations + clean propagation = best long-term stability.

3. Checkpoint/Restart

Raw binary + text header + CRC32 Zero dependencies
  • Header: ASCII magic, key-value metadata (N, L, step, time, params), endianness marker
  • Data: Interior points only (ghosts reconstructed). Sequential per field, per block for AMR.
  • Footer: CRC32 checksum. Ring buffer of 2 files.
  • Performance: N=128, 31 fields: ~512 MB. On NVMe at 3 GB/s: 0.17 sec.
  • Async: fork() for CPU (copy-on-write), pthread + double buffer for GPU.

4. Waveform Extraction

StepWhat
1Compute Psi4 on grid
2Interpolate onto spheres at r = {50, 75, 100, 150, 200} M
3Decompose into (l,m) modes via s=−2 spherical harmonics
4Output r·Psi4lm(t) time series
5FFI to strain + 1/r extrapolation (Python post-processing)

Two extraction approaches: fixed-radius + extrapolation (standard, <1% accuracy for BBH) and CCE via SpECTRE worldtube (gauge-invariant at J+, captures GW memory, needed for LISA/3G). CCE worldtube at r~25M sits in the AMR-refined region, sidestepping wave zone resolution issues. ~300 LOC C for worldtube output.

The extraction sphere must not cross AMR refinement boundaries. Constrain regridding so the sphere's bounding box stays within one level (~20 lines in criterion.c).

3D output: XDMF + raw binary for ParaView/VisIt. Each AMR block is a <Grid> element. ~200 lines of C.

6. Performance Optimizations

Quick Wins

LTO (-flto) 5–15% CPU

Add -flto to CFLAGS_OPT in the Makefile (CPU only; GPU LTO broken in GCC 15). Enables cross-TU inlining of ccz4_rhs_point through the function pointer in backend_cpu.c. One line change.

__restrict__ on RHS pointers 3–8%

The compiler cannot assume rhs[f] and src[FIELD_CHI] don't alias, so it re-loads from memory after every write. Add __restrict__ to ccz4_rhs_point signature and backend dispatch functions. GPU-safe. 5 lines.

Conditional EM allocation 19% memory

The 6 EM fields (Ei, Bimag) are always allocated even when --em is off. NUM_FIELDS=31 is baked into every allocation. Check em_enabled in grid_alloc() and skip EM fields. Saves ~970 MB at N=256, ~4.5 GB for 200-block AMR. ~20 lines.

Hoist em_enabled branch ~5% GPU

In backend_cpu.c:176 and backend_gpu.c:227, the EM dispatch check is inside the innermost loop. Hoist outside, use two code paths. Marginal on CPU (branch predictor), ~5% on GPU (eliminates warp divergence).

CPU

Fused d1/d2 stencil 15–20% CPU, 5–10% GPU

11 fields need both d1 and d2 per direction (chi, lapse, 6×h_ij, 3×shift). Currently loads the same 7 stencil points twice. A fused fd_d1_d2() halves the load count: 33×3 = 99 redundant load sequences eliminated.

static inline void fd_d1_d2(const double *f, int idx, int s, double dx,
                            double *d1, double *d2) {
    double fm3=f[idx-3*s], fm2=f[idx-2*s], fm1=f[idx-s], f0=f[idx];
    double fp1=f[idx+s], fp2=f[idx+2*s], fp3=f[idx+3*s];
    *d1 = (-1.0/60*fm3 + 3.0/20*fm2 - 3.0/4*fm1
           + 3.0/4*fp1 - 3.0/20*fp2 + 1.0/60*fp3) / dx;
    *d2 = (1.0/90*fm3 - 3.0/20*fm2 + 3.0/2*fm1
           - 49.0/18*f0
           + 3.0/2*fp1 - 3.0/20*fp2 + 1.0/90*fp3) / (dx*dx);
}
Common subexpression elimination 10–20% FLOPs

chris.ULL[m][kk][ll] is reused across Ricci, Gamma RHS, and A_ij RHS. Products like lapse * K and h_UU[i][j] contracted with various tensors appear multiple times. The compiler's CSE pass is limited by C aliasing rules. Manual extraction of Christoffel products and metric contractions is low effort. NRPy+ reports ~21% instruction reduction via SymPy CSE (arXiv:2501.14030). ~50 lines.

Symmetric tensor raise 2–3%

raise_all_2() in tensor_utils.h computes all 9 entries of Aij but only 6 are unique. Compute diagonal (3) + upper triangle (3) and copy: 54 FMAs → 36 (33% reduction). ~20 lines.

Derivative precomputation for mixed d2 30–50% fewer loads

fd_d2_mixed() uses a 7×7 = 49-point stencil (6th-order). Store first derivatives in scratch arrays, then compute mixed second derivatives as 1D stencils on the stored d1 values: 7 loads instead of 49 per mixed pair. 11 fields × 3 mixed direction pairs = 33 instances. Requires scratch storage for d1 arrays.

Interior/boundary RHS split 10–20% AMR

Compute interior cells' RHS (no ghost dependency) while ghost exchange runs concurrently. Interior cells vastly outnumber boundary cells. Used by GR-Athena++, SpECTRE, ExaGRyPE. Medium effort (~150 lines).

GPU

Persistent pack allocation 10–20%

Lattice rebuilds the entire meshblock_pack_t every time step: malloc + field copy + omp target enter data + compute + omp target exit data + store + free. AthenaK keeps all field data on GPU permanently, only rebuilding after regridding. Eliminates two full-buffer host–device transfers per step. ~100 lines.

Device-side ghost exchange 2–5x GPU overall

The single largest GPU bottleneck. backend_gpu.c:879-910 syncs the entire pack to host, runs all 5 ghost exchange phases on CPU, then syncs back. For 100 blocks at 643: ~1.6 GB round-trip per CK45 stage, 5 stages = ~8 GB/step of PCIe traffic. AthenaK does all ghost exchange on-device. Phase 0+1 (same-level copy) is trivially parallelizable as a GPU kernel. ~300 lines.

Eliminate per-thread GPU overhead 15–30% occupancy

Every GPU thread in backend_gpu.c:205-221 constructs a grid_t on stack (~872 bytes) via memset and builds two 31-element pointer arrays (~496 bytes). Total: ~1.4 KB per thread. Grid dimensions are identical for all threads in a block. Pass as kernel parameters instead. ~30 lines.

Kernel splitting for occupancy 20–40% GPU

The CCZ4 RHS kernel uses ~400 registers/thread = ~25% occupancy on A100. Split into Phase A (derivatives + Christoffels, ~200 registers) and Phase B (Ricci + RHS assembly from scratch buffer, ~200 registers). Each phase achieves ~75–80% occupancy. ~400 lines.

Optimal block size 2–30x GPU

Parthenon-VIBE benchmarks (arXiv:2509.19701) show N_block=16 makes GPU slower than 96-core CPU. N_block=32 is minimum for GPU; 64 is optimal for weak scaling. Already a runtime parameter in Lattice. Zero code changes.

Reorder d2 for instruction cache 10–20% GPU

Reorder second derivative computations to maximize instruction reuse (sort d2[min(i,j)][max(i,j)]). Fits within the 32 KB instruction cache. NR101 blog reports ~20% GPU speedup. Low effort.

Memory

Already sound: CK45 uses 3 memory blocks (optimal) vs Classic RK4's 4. No malloc/free inside time-stepping loops. Page-alignment waste is <4 KB per block. Ghost width=4 is required for 6th-order FD + 8th-order KO (unavoidable). At N_block=16: 4.1x ghost overhead; N_block=32: 1.95x; N_block=64: 1.51x.

7. Mathematical Methods

Dense output for temporal interpolation HIGH IMPACT

Current quartic interpolation at coarse–fine boundaries stores 5 quantities per point. RK4 dense output achieves 4th-order temporal accuracy using the 4 stage vectors + pre-step state:

y(t_n + θ·h) = y_n + h·[b1(θ)·k1 + b2(θ)·k2 + b3(θ)·k3 + b4(θ)·k4]
b1 = θ - 3θ2/2 + 2θ3/3
b2 = b3 = θ2 - 2θ3/3
b4 = -θ2/2 + 2θ3/3

CarpetX (arXiv:2503.09629) uses this to achieve 4th-order convergence at AMR boundaries with fewer prolongation operations. Simpler than the current fields_old/fields_older/rhs_old/rhs_older scheme. ~200 lines.

Caveat: Works naturally with classic RK4 (k1–k4 explicit). CK45's 2N storage overwrites stage vectors, so subcycling steps would need to use classic RK4.
Optimized-stability 2N RK methods 20–50% fewer steps

Niegemann et al. (2012) constructed 2N methods with 8–14 stages optimized for maximum CFL rather than higher order. 1.5–2x larger stable timestep at the cost of more stages. Net savings if CFL-limited. Swapping in new coefficients is trivial (same CK_A[s], CK_B[s] infrastructure).

Ketcheson (2010) found 2S methods achieving 4th order in only 4 stages (vs CK45's 5), saving 20% RHS evaluations. Different update formula but similar memory.

P-ERK (Paired Explicit Runge-Kutta) 2–5x on AMR

Different AMR blocks use different RK stage counts based on local stiffness. Coarse blocks (80% of mesh) get fewer stages. Reported 1.5–5x speedup for 4–6 AMR levels (arXiv:2403.05144). Fourth-order P-ERK now exists (arXiv:2408.05470).

Caveat: Very high implementation complexity. Requires spectral radius estimation per block. No existing NR implementation.
Mixed-order stencils near punctures 10–20% on fine levels

Use 4th-order FD (5-point) on finest AMR levels wrapping the puncture (where solution is only C2–C4), 6th-order elsewhere. Both already implemented in finite_diff.h (compile-time FD_ORDER). Making it per-block at runtime requires two RHS versions or function pointer dispatch. Medium effort.

KO dissipation stage reduction Few %

Apply Kreiss-Oliger dissipation at 1 RK stage instead of all 5. Saves ~80% of KO computation. Low effort but stability risk near punctures.

9. Long-term Scaling

Multi-GPU 1.5–3.5x on 4 GPUs

Split meshblock_pack across devices. Morton ordering provides spatial locality for partitioning.

MPI domain decomposition Linear scaling

Partition Morton-sorted blocks across MPI ranks. AthenaK demonstrates 80% scaling to 65,536 GPUs.

Why 6th-Order FD

6th order is the production standard among FD-based NR codes (AthenaK, GR-Athena++, BAM). We upgraded in February 2026 with zero infrastructure changes — GHOST_WIDTH=4 already supported 6th-order FD + 8th-order KO. The key numbers:

  • 170x cheaper than 4th order at ε=10−6 (despite 1.63x more FLOPs/point, you need far fewer grid points)
  • N=91 at 6th order matches N=256 at 4th order for the same accuracy
  • Prolongation/restriction matched at 6th order — no operator mismatch at AMR boundaries

Going to 8th order is not worth it: requires ghost=5 (breaking change to grid, AMR, boundaries), puncture solutions are C2–C4 (saturates beyond 6th), and RK4 time error O(h4) dominates.
