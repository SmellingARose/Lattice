1. Position-Dependent Eta

The single most critical change for N-body simulations. Without it, unequal-mass and hierarchical-merger dynamics are unstable.

The Problem

The Gamma-driver shift condition uses a global constant eta to damp gauge oscillations. For a single equal-mass binary, eta=1.0 works. But:

  • Unequal mass: A constant eta that's right for M=5 is wrong for M=0.5. The damping timescale should be proportional to the local BH mass.
  • CFL-like constraint: Schnetter (arXiv:1003.0859) showed eta introduces a resolution-independent timestep limit. On coarse AMR levels with large dt, constant eta can violate this.
  • Hierarchical mergers: After two BHs merge, the remnant has mass M1+M2, requiring different eta than either progenitor. A constant eta cannot adapt.

Options Compared

Option A: eta(x) = eta_0 / W(x) Recommended

Where W = sqrt(chi). Near a puncture, chi→0 so eta→∞ (strong damping). Far away, chi→1 so eta→eta_0. Each BH automatically gets the right damping for its mass.

Used by GRChombo 25-BH simulation (arXiv:2505.01495).

Option B: eta(x) = eta_0 / alpha

Simpler — uses lapse instead of chi. Near a puncture, 1+log lapse gives alpha∼sqrt(chi), so behavior is similar. Slightly less clean mathematically since alpha depends on gauge choice.

Used by some Einstein Toolkit setups.

Implementation 1 line change
// ccz4_rhs.c:476 — current
rhs_B[ii] = ... + rhs_Gamma[ii] - p->gauge.eta * B[ii];

// Proposed: position-dependent eta
double W = sqrt(fmax(chi, 1e-10));
double eta_local = p->gauge.eta / W;
rhs_B[ii] = ... + rhs_Gamma[ii] - eta_local * B[ii];

Add --eta-mode constant|conformal flag. Default to conformal for Phase 3.

2. Spatially Varying KO Dissipation

Already implemented Done

Lattice already has all three techniques from arXiv:2404.01137:

  • CAKO — sigma_eff = sqrt(chi) * sigma. Suppresses dissipation near punctures where steep gradients are physical (trumpet solution), not noise.
  • CAHD — Constraint-Adjusted Hamiltonian Damping. Adds chi-weighted Hamiltonian constraint to dt(chi).
  • SSL — Slow-Start Lapse. Gaussian-damped relaxation to prevent initial gauge pulse.
  • Per-field sigma — sigma=0.99 for gauge fields, sigma=0.3 for physical fields.

For N=10+, these are even more critical: N regions where chi→0, plus interaction zones between punctures where chi is depressed. CAKO handles all of this automatically.

3. 6th-Order Finite Differences

The single biggest accuracy improvement available. Ghost width is already sufficient — no memory layout change needed.

6th order fits within ghost=4. 8th order requires ghost=5, which changes memory layout, AMR ghost exchange, and prolongation — a much larger refactor. AthenaK uses 6th as their standard NR configuration.

Exact Stencil Coefficients

/* 6th-order first derivative */
static inline double fd_d1_6(const double *f, int idx, int s, double dx) {
    return (-1.0/60*f[idx-3*s] + 3.0/20*f[idx-2*s] - 3.0/4*f[idx-s]
            + 3.0/4*f[idx+s] - 3.0/20*f[idx+2*s] + 1.0/60*f[idx+3*s]) / dx;
}

/* 6th-order second derivative */
static inline double fd_d2_6(const double *f, int idx, int s, double dx) {
    return (1.0/90*f[idx-3*s] - 3.0/20*f[idx-2*s] + 3.0/2*f[idx-s]
           - 49.0/18*f[idx]
           + 3.0/2*f[idx+s] - 3.0/20*f[idx+2*s] + 1.0/90*f[idx+3*s]) / (dx*dx);
}

/* 8th-order KO dissipation (pairs with 6th-order FD) */
static inline double fd_ko_8(const double *f, int idx, int s, double dx) {
    return (1*f[idx-4*s] - 8*f[idx-3*s] + 28*f[idx-2*s] - 56*f[idx-s]
           + 70*f[idx]
           - 56*f[idx+s] + 28*f[idx+2*s] - 8*f[idx+3*s] + 1*f[idx+4*s])
          / (256.0 * dx);
}

AMR Prolongation Interaction

Keep 4th-order prolongation Pragmatic

Bulk convergence is 6th-order. Refinement boundaries degrade to ~4th. Acceptable if boundaries are far from strong-field region. AthenaK and GR-Athena++ both started this way.

Upgrade to 6th-order prolongation Ideal

6-point Lagrange per dimension (216 points in 3D vs current 64). Full 6th-order everywhere including refinement boundaries. Per Mongwane (arXiv:1504.07609), needed for clean convergence at boundaries.

Time Integrator Note

RK4 is 4th-order in time. With 6th-order spatial, temporal error O(dt^4) could bottleneck. In practice, AthenaK and GR-Athena++ both use RK4 + 6th-order spatial and accept this — spatial error dominates at production resolutions. A smaller CFL factor (~0.15 vs 0.25) can push temporal error below spatial.

4. CCZ3 Formulation

A formulation change that eliminates late-time instabilities, enabling runs 100x longer than standard CCZ4.

The Problem with CCZ4 at Late Times

arXiv:2501.01055 (Bezares, Bona, Palenzuela 2025) identifies that standard CCZ4's kappa1 damping of momentum constraint violations causes energy to accumulate in unphysical modes. This produces a late-time instability at ~10^3-10^4 M that no amount of parameter tuning can fix.

Three Formulations Compared

AspectCCZ4 (current)CCZ4' (modified)CCZ3
Theta evolved?YesYesNo (removed)
Hamiltonian dampingkappa1 via Thetakappa1 via Theta (can increase)None
Momentum dampingkappa1 * Z_i (causes instability)None (propagates freely)None (propagates freely)
Evolved fields252524 (no Theta)
Long-term stability~10^3-10^4 M10^5 M10^5 M
Short-term accuracyBest (active cleaning)GoodAcceptable
The key insight is counterintuitive: removing constraint damping makes the simulation more stable. Momentum violations propagate to the boundary and leave the domain (via Sommerfeld BCs) instead of accumulating as unphysical energy.

Implementation in Lattice

CCZ4' (minimal change) Recommended first

Remove one term from the Gamma equation. Retains Theta for Hamiltonian cleaning:

// ccz4_rhs.c:373 — remove this line for CCZ4'
rhs_Gamma[i] += ... - 2.0 * kappa1_times_lapse * Z_over_chi[i];  // DELETE

Add --formulation ccz4|ccz4p|ccz3 runtime flag.

CCZ3 (full simplification) Maximum stability

Remove Theta entirely. In ccz4_rhs.c:

  • Set Theta = 0, skip d1_Theta computation
  • Remove entire rhs_Theta computation
  • K - 2*Theta becomes just K everywhere
  • Remove kappa1 * Z_over_chi from Gamma equation
  • Remove kappa1 * Theta from K equation

Synergy with 6th-Order FD

CCZ3 removes the constraint-damping safety net, relying on clean violation propagation. 6th-order FD generates fewer constraint violations in the first place (smaller truncation error). The combination is synergistic: less violation generation + clean propagation = best long-term stability. No known incompatibilities.

5. Checkpoint/Restart

Without this, production runs are impossible. A 40-hour inspiral that crashes loses everything.

Format Options

FormatDependenciesWrite SpeedSelf-describingParaView/VisIt
Raw binary + text headerNoneMaximum (fwrite)Text headerNo (checkpoint only)
HDF5libhdf5 (~1.5 MB)90% of rawYesYes (native)
ADIOS2libadios2 + MPIBest at scaleYesYes (via plugin)
Recommended: Raw binary + text header Zero dependencies

Matches Lattice's philosophy. Design:

  • Header: ASCII magic number, key-value metadata (N, L, step, time, params), terminated by DATA_START
  • Endianness marker: Write known double (1.0) — reader checks if byte-swap needed
  • Field data: Interior points only (ghosts reconstructed from BCs). Sequential per field, per block for AMR.
  • Footer: CRC32 checksum of entire file
  • Ring buffer: Alternate between checkpoint_A.bin and checkpoint_B.bin

At N=128 with 31 fields: ~512 MB per checkpoint. On NVMe at 3 GB/s: ~0.17 seconds.

Async Strategies

fork() (CPU builds) Simplest

Child process inherits copy-on-write memory snapshot. Writes to disk while parent continues evolving. Zero additional memory. ~5 lines of code.

pthread + double buffer (GPU builds) For GPU

memcpy field data to staging buffer, hand off to background thread. Needed because GPU memory may not survive fork(). Extra ~500 MB for staging buffer.

Extraction Method Comparison

Fixed-radius + extrapolation Recommended

Compute Psi4 on spheres at 4-6 radii, extrapolate to r→∞. Accuracy <1% for BBH. Standard approach — what all codes used for first production waveforms.

Requires: sphere interpolation, s=-2 Y_lm decomposition, Gauss-Legendre quadrature.

Cauchy-Characteristic Extraction (CCE) Long-term

Evolve Einstein equations on null characteristics to future null infinity. Eliminates all finite-radius artifacts, captures GW memory. AthenaK feeds worldtube data to SpECTRE's CCE module.

Essentially a separate PDE solver. Defer to Phase 3+.

Mode Decomposition

Spin-weight s=-2 spherical harmonics via the Goldberg formula. For l_max=4: need at least 5 theta points (Gauss-Legendre) x 9 phi points (uniform). In practice, use 2x oversampling: 10×18 = 180 points per sphere. The integral:

Psi4^{lm}(t,r) = ∫ Psi4(t,r,θ,φ) * conj(_{-2}Y_{lm}(θ,φ)) sin(θ) dθ dφ

LIGO Catalog Requirements

Per LIGO-T1500606 (arXiv:1703.01076), a catalog entry needs: strain modes h^{lm}(t) for l=2..4+, simulation metadata (masses, spins, eccentricity), remnant properties (M_f, a_f, kick velocity), and convergence error estimates. The C code outputs raw Psi4 modes; a Python post-processing script converts to LIGO HDF5 format using h5py + romSpline.

8. N=10+ Black Holes: What's Needed

Initial Data

The existing FAS multigrid solver already handles arbitrary N. The Bowen-York A_ij is a linear superposition (exact for N bodies). Only the Hamiltonian constraint needs a nonlinear solve, which the solver already does. Key finding from Lousto & Zlochower (arXiv:1004.1353): for N≥3, you must solve the Hamiltonian constraint — the raw Brill-Lindquist superposition gives different dynamics and waveforms.

Minimal changes for N=10+
  • Raise MAX_PUNCTURES from 16 to 32+ in params.h (trivial)
  • Position-dependent eta (see Section 1)
  • Validate multigrid solver with N=3 test case
  • Dynamic regridding every 4-8 steps (currently every step may be too costly)

9. GPU Performance Infrastructure

Persistent Pack

Currently the meshblock pack is allocated, loaded, computed, stored, and freed every single timestep. For a static mesh between regrids, this wastes ~4 GB of memcpy per step. AthenaK creates packs once and reuses them — the pack IS the canonical data store.

Change: Build pack at simulation start (and after regrid). Keep data on-device. Only sync for diagnostics/output.

Impact: 10-20% GPU speedup. Eliminates per-step alloc/free/copy overhead.

Block Size

N_blockGhost overheadUseful compute fractionGPU efficiency
16 (current AMR)70%30%Below threshold (Parthenon-VIBE)
3249%51%Good
64 (AthenaK default)30%70%Optimal

Parthenon-VIBE (arXiv:2509.19701): N=16 blocks make a single GPU slower than a 96-core CPU. N=32 is the minimum for GPU efficiency. N_block is already a runtime parameter — just change the default.

LTO (-flto)

Add -flto for CPU builds only. GPU builds (-foffload=nvptx-none) have known incompatibilities with LTO in GCC 15 (lto-wrapper / mkoffload failures). Use conditional Makefile logic:

ifeq ($(BACKEND),cpu)
    CFLAGS_OPT += -flto
endif
