1. Position-Dependent Eta

The single most critical change for N-body simulations. Without it, unequal-mass and hierarchical-merger dynamics are unstable.

Problem: A global constant eta that's right for M=5 is wrong for M=0.5. Schnetter (arXiv:1003.0859) showed eta introduces a resolution-independent timestep limit. On coarse AMR levels, constant eta violates this.

Option A: eta(x) = eta_0 / W(x) Recommended

Where W = sqrt(chi). Near a puncture, chi→0 so eta→∞ (strong damping). Used by GRChombo 25-BH simulation (arXiv:2505.01495).

Option B: eta(x) = eta_0 / alpha

Uses lapse instead of chi. Near a puncture, 1+log gives alpha∼sqrt(chi), so behavior is similar. Slightly less clean since alpha depends on gauge.

Implementation 1 line change
// ccz4_rhs.c — current: constant eta
rhs_B[ii] = ... + rhs_Gamma[ii] - p->gauge.eta * B[ii];

// Proposed: position-dependent eta
double W = sqrt(fmax(chi, 1e-10));
double eta_local = p->gauge.eta / W;
rhs_B[ii] = ... + rhs_Gamma[ii] - eta_local * B[ii];

2. Spatially Varying KO Dissipation Done

Already implemented: CAKO (sigma_eff = sqrt(chi) * sigma), CAHD (constraint-adjusted Hamiltonian damping), SSL (slow-start lapse), per-field sigma. All from arXiv:2404.01137. For N=10+, CAKO handles all N puncture regions automatically.

3. Finite Difference Order: The Mathematical Case for 6th

This is the single biggest accuracy improvement available. We prove mathematically that 6th order is the optimal choice for our code, and that going higher gives diminishing returns.

For a target accuracy ε on a 3D grid with CFL timestep:

W(ε, p) = N4 · F(p) where N ~ (ε / |Cp|)−1/p

The −4/p exponent is the key: higher order means cost grows much more slowly with accuracy.

  • At 4th order: halving ε costs 24/4 = 2x more work
  • At 6th order: halving ε costs 24/6 = 1.59x more work
  • At 8th order: halving ε costs 24/8 = 1.41x more work

3.6 Why Not 8th Order? Diminishing Returns

The pure-math analysis assumes smooth solutions and infinite precision. Five effects cap the benefit at 6th order for CCZ4 puncture evolutions:

1. Ghost zones: infrastructure break

8th order requires ghost=5, which changes grid allocation, AMR ghost exchange, prolongation stencils, and boundary conditions. 6th order needs ghost=4 — what we already have.

2. Puncture regularity: fields are not smooth

Near a moving puncture, chi transitions from 1/r2 to ~r (trumpet). Per Hannam et al. (gr-qc/0606099), the solution is effectively C2–C4 near the puncture. The higher derivatives f(p+1) blow up, so the theoretical ε ~ hp scaling saturates. Beyond ~6th order, you gain nothing in the innermost cells.

3. AMR prolongation mismatch

Our prolongation is 4th-order (5-point Lagrange, from AthenaK). At refinement boundaries, interpolation error is O(h5). With 6th-order FD, the mismatch is one order — acceptable since boundaries are a small grid fraction. With 8th-order FD, prolongation becomes the dominant error source.

4. Time integration: RK4 is 4th-order

With dt ~ h (CFL), time error is O(h4). At 6th-order spatial, the spatial prefactor |C6| = 1/140 is small enough that spatial error stays subdominant at production resolutions. At 8th-order spatial, the O(h4) time error completely dominates — the extra spatial accuracy is wasted.

5. Boundary condition order

Sommerfeld BCs are ~2nd-order accurate regardless of interior stencil. Mitigated by placing boundaries far from sources, but caps the global (L-infinity) convergence order.

/* 6th-order first derivative — 7 points, ghost=3 */
static inline double fd_d1_6(const double *f, int idx, int s, double dx) {
    return (-1.0/60*f[idx-3*s] + 3.0/20*f[idx-2*s] - 3.0/4*f[idx-s]
            + 3.0/4*f[idx+s] - 3.0/20*f[idx+2*s] + 1.0/60*f[idx+3*s]) / dx;
}

/* 6th-order second derivative — 7 points, ghost=3 */
static inline double fd_d2_6(const double *f, int idx, int s, double dx) {
    return (1.0/90*f[idx-3*s] - 3.0/20*f[idx-2*s] + 3.0/2*f[idx-s]
           - 49.0/18*f[idx]
           + 3.0/2*f[idx+s] - 3.0/20*f[idx+2*s] + 1.0/90*f[idx+3*s]) / (dx*dx);
}

/* 8th-order KO dissipation (pairs with 6th-order FD) — 9 points, ghost=4 */
static inline double fd_ko_8(const double *f, int idx, int s, double dx) {
    return (1*f[idx-4*s] - 8*f[idx-3*s] + 28*f[idx-2*s] - 56*f[idx-s]
           + 70*f[idx]
           - 56*f[idx+s] + 28*f[idx+2*s] - 8*f[idx+3*s] + 1*f[idx+4*s])
          / (256.0 * dx);
}

4. CCZ3 Formulation

arXiv:2501.01055 shows standard CCZ4's kappa1 damping of momentum constraints causes energy to accumulate in unphysical modes, producing a late-time instability at ~103–104 M.

AspectCCZ4 (current)CCZ4′CCZ3
Theta evolved?YesYesNo (removed)
Momentum dampingkappa1 * Z_i (unstable)None (propagates out)None (propagates out)
Long-term stability~103–104 M105 M105 M
Evolved fields252524
The key insight is counterintuitive: removing constraint damping makes the simulation more stable. Momentum violations propagate to the boundary and leave (via Sommerfeld BCs) instead of accumulating.
Implementation CCZ4′ first, then CCZ3
// CCZ4′: remove this one line from the Gamma equation
rhs_Gamma[i] += ... - 2.0 * kappa1_times_lapse * Z_over_chi[i];  // DELETE

// CCZ3: also set Theta=0, skip rhs_Theta, "K - 2*Theta" becomes just "K"

Add --formulation ccz4|ccz4p|ccz3 runtime flag.

Synergy with 6th-order FD: CCZ3 removes the damping safety net, relying on clean violation propagation. 6th-order FD generates fewer violations (smaller truncation error). Less generation + clean propagation = best long-term stability.

5. Checkpoint/Restart

Without this, production runs are impossible. A 40-hour inspiral that crashes loses everything.

Raw binary + text header + CRC32 Zero dependencies
  • Header: ASCII magic, key-value metadata (N, L, step, time, params), endianness marker
  • Data: Interior points only (ghosts reconstructed). Sequential per field, per block for AMR.
  • Footer: CRC32 checksum. Ring buffer of 2 files.
  • Performance: N=128, 31 fields: ~512 MB. On NVMe at 3 GB/s: 0.17 seconds.
  • Async: fork() for CPU (copy-on-write snapshot), pthread + double buffer for GPU.

Psi4 on spheres at 4-6 radii, extrapolate to r→∞. Accuracy <1% for BBH. Standard approach.

Limitation: spheres at r=50-100M on coarsest AMR level.

CCE via SpECTRE worldtube Next-gen detectors

Output metric on worldtube at r=20-25M (AMR-refined region), feed to SpECTRE CCE. Gauge-invariant at J+, captures GW memory. ~300 LOC C for worldtube output.

Worldtube in refined region sidesteps wave zone resolution problem.

Spectral filter: f_lm *= exp(-36 * (l/l_max)^8) kills grid noise, preserves physics modes.

The extraction sphere must not cross AMR refinement boundaries. At crossings, data drops to prolongation order and CCE propagates that noise. Constrain regridding so the sphere's bounding box stays within one level (~20 lines in criterion.c).

The Accuracy Chain

Every link matters for next-gen quality Critical

CCE cannot fix evolution errors. For LISA/3G, all four must be addressed:

  • 6th-order FD — reduces truncation error at every point including the worldtube
  • 6th-order prolongation — prevents AMR boundaries from injecting 4th-order error
  • Worldtube at r~25M — in the refined AMR region, not on the coarse root grid
  • CCE — gauge-invariant propagation to J+, GW memory, no finite-radius artifacts

9. CPU Performance Optimizations

LTO (-flto) Trivial, 5-15% CPU

Add -flto to Makefile for CPU builds only (GPU LTO is broken in GCC 15). Enables cross-TU inlining of ccz4_rhs_point through the function pointer in backend_cpu.c. Full register allocation across the entire 500-line RHS kernel.

Fused d1/d2 stencil Low effort, 10-15% CPU

11 fields need both d1 and d2 per direction (chi, lapse, 6×h_ij, 3×shift). Currently loads the same 5 stencil points twice. Fusing into fd_d1_d2() saves 33×3 = 99 redundant load sequences.

static inline void fd_d1_d2(const double *f, int idx, int s, double dx,
                             double *d1, double *d2) {
    double fm2=f[idx-2*s], fm1=f[idx-s], f0=f[idx], fp1=f[idx+s], fp2=f[idx+2*s];
    *d1 = ((1.0/12)*fm2 - (2.0/3)*fm1 + (2.0/3)*fp1 - (1.0/12)*fp2) / dx;
    *d2 = (-(1.0/12)*fm2 + (4.0/3)*fm1 - (5.0/2)*f0 + (4.0/3)*fp1 - (1.0/12)*fp2) / (dx*dx);
}
Fused RHS + CK45 update Medium effort, 15-25% CPU

Eliminate the intermediate RHS buffer. Instead of writing ~500 MB of RHS then reading it back in the CK45 update kernel, fuse both inside ccz4_rhs_point. Saves one full memory pass per stage (5 stages = 5 GB avoided at N=128).

10. GPU Performance Optimizations

Persistent pack 10-20% GPU

Currently the meshblock pack is allocated, loaded, computed, stored, and freed every timestep. Build pack once; reuse across steps; invalidate only on regrid. Eliminates ~4 GB of memcpy per step.

Selective GPU transfer (ghost slabs only) 3-8x transfer reduction

Ghost exchange currently syncs the entire data buffer to host and back (684 MB round-trip for 200 blocks). Ghost slabs are ~12% of that. Smart slicing reduces PCIe traffic by 4-8x.

GPU-native ghost exchange 2-5x overall GPU

Run all 5 phases of ghost exchange as GPU kernels. Eliminates the host round-trip entirely. The biggest single GPU optimization. Same-level exchange is device-to-device copies; prolongation/restriction are natural GPU kernels.

Kernel splitting for occupancy 20-40% GPU

Split ccz4_rhs_point into two stages: (1) all derivatives, (2) algebra+Christoffels+Ricci. Currently ~400 registers per thread = 15% occupancy on A100. Splitting doubles occupancy.

Larger AMR blocks (323) Config change

At N=16 with ghost=4: 70% overhead. At N=32: 49%. At N=64: 30%. Parthenon-VIBE warns 163 makes GPU slower than 96-core CPU. N_block is already a runtime parameter.

11. Long-term Scaling

Multi-GPU 1.5-3.5x on 4 GPUs

Split meshblock_pack across devices. Morton ordering provides spatial locality for partitioning. Inter-device ghost exchange via host staging.

MPI domain decomposition Linear scaling

Partition Morton-sorted blocks across MPI ranks. AthenaK demonstrates 80% scaling to 65,536 GPUs. The subcycling complication: fine blocks needing coarse neighbor data across rank boundaries need temporal interpolation.

P-ERK multi-rate RK 2-5x on AMR

Different blocks use different RK stage counts based on local stiffness. Outer 80% of blocks (non-stiff) get fewer stages, saving 2-5x total work.
