Deep-dive document. Explains the coarse-buffer multi-level ghost exchange (Phases 2–4 of ghost_exchange_multilevel) and the Phase 3.5 dimension-sweep bug fix.
Last updated: 2026-02-17  |  Source: src/amr/ghost_exchange.c

The Problem: Cross-Level Ghost Zones

In a uniform grid, ghost zone exchange is simple: every block has neighbors at the same resolution. Copy a slab of interior data from the neighbor into the block's ghost region. Done.

With AMR, fine blocks at level L+1 may sit next to coarser blocks at level L. The fine block's ghost cells need data that doesn't exist at fine resolution — it lives on the coarser grid. Someone needs to interpolate (prolongate) coarse data to fill those fine ghost cells.

This is the multi-level ghost exchange problem: how to fill ghost zones when neighbors exist at different refinement levels.

Why not just prolongate directly from the coarse neighbor?

Because the prolongation stencil is wide (5 points per direction for 4th-order accuracy). A fine block's ghost cell near a corner might need coarse data that lives in the coarse block's ghost zone, which itself might come from another block, or from a domain boundary. You can't just read from the coarse block's interior — you need a complete, ghost-filled coarse representation around the fine block.

The AthenaK Coarse-Buffer Pattern

The solution (from AthenaK / Athena++) is elegant: each fine block carries its own half-resolution buffer.

coarse_buf: a private grid_t at the parent level's resolution covering the same physical domain as the fine block, plus ghost zones. Fine block: N = 32, dx = 0.1, domain = [0, 3.2] coarse_buf: N = 16, dx = 0.2, domain = [0, 3.2] (same physical extent) ghost = 4 on each side (same ghost width) Ntotal = 24 (N + 2*ghost = 16 + 8) The coarse_buf is block-local. No other block writes to it. All cross-level communication goes through this buffer.

The key insight: by filling the coarse_buf completely (interior + ghosts), the prolongation stencil can always find valid data regardless of where the fine ghost cell is located — faces, edges, or corners.

The 5-Phase Pipeline

The complete multi-level ghost exchange runs in ghost_exchange_multilevel(). Every phase is embarrassingly parallel per block — no cross-block writes.

ghost_exchange_multilevel(mesh_t *m) Phase 0+1 exchange_same_level() Fine siblings share ghost data | (same as uniform grid exchange) v Phase 2 restrict_to_coarse_buf() Fine interior --> coarse_buf interior | (4th-order Lagrange, block-local) v Phase 3 fill_coarse_buf_ghosts() Coarse_buf ghosts from neighbors: | same-level: buf <--> buf exchange | coarser: coarse grid --> buf v Phase 3.5 fill_coarse_buf_boundary() Domain boundaries: quadratic extrapolation | (only faces where nblevel < 0) v Phase 4 prolongate_from_own_ Coarse_buf --> fine ghost zones coarse_buf() (5-point Lagrange, skip same-level dirs)

After Phase 4, every fine leaf block has valid ghost data in all 26 directions, regardless of whether the neighbor is same-level, coarser, or a domain boundary.

Phase 0+1: Same-Level Exchange

Standard 26-neighbor ghost exchange, applied level by level (coarsest first). For each pair of same-level leaf blocks that are neighbors, copy interior data into the other's ghost zone. This is identical to uniform-grid ghost exchange.

Fine block interior (fields[])Fine block ghost zones (fields[])Same-level leaf pairs at each level

After this phase, any fine ghost cell whose neighbor is also a fine leaf at the same level is correctly filled. Ghost cells facing coarser neighbors or domain boundaries remain stale.

Phase 2: Restrict Fine Interior to coarse_buf

Each fine leaf block restricts its own interior data into its own coarse_buf interior. Uses a 4th-order symmetric Lagrange stencil (4 fine cells per coarse cell per direction, 64 fine cells total in 3D). Falls back to 2nd-order (8-cell average) where the stencil reaches outside the fine interior.

ReadsWritesScope
Fine block interior (fields[])coarse_buf interior (fields[])Each fine leaf block independently

After this phase, the coarse_buf interior contains a 4th-order accurate coarse representation of the fine block's data. The coarse_buf ghost zones are still empty.

Phase 3: Fill coarse_buf Ghost Zones

For each of 26 neighbor directions, fill the coarse_buf's ghost zone from the appropriate source:

  • Same-level sibling (neighbor at level L+1): Copy from the sibling's coarse_buf interior. Both coarse_bufs have the same N and dx, so this is a standard grid-pair exchange via exchange_grid_pair().
  • Coarser neighbor (neighbor at level L): Copy from the coarse neighbor's main grid. The coarse grid and coarse_buf share the same dx, so an integer index-offset mapping suffices. Implemented in copy_from_coarse_grid().
  • Domain boundary (nblevel < 0): Skip — handled by Phase 3.5.
ReadsWritesScope
Sibling coarse_buf interior, or coarse neighbor grid interiorcoarse_buf ghost zonesEach fine leaf block, 26 directions
Subtle issue: The ghost_range(0, ...) call for non-ghost directions returns the interior range [ghost, ghost+N). This means that when copying the z+ ghost slab, only cells at interior x and interior y are filled. Cells at ghost x or ghost y positions within the z+ slab are not touched. This is by design — those edge/corner cells will be filled by Phase 3.5 if they are domain boundaries, or were already filled by an earlier Phase 3 neighbor copy for a different direction. But this design assumption is where the dimension-sweep bug manifests.

Phase 3.5: Boundary Extrapolation on coarse_buf Bug-Fix Critical

At domain boundaries (faces where nblevel < 0), there is no neighbor to copy from. Phase 3.5 fills these boundary ghost cells by quadratic extrapolation from interior data — a 3-point Lagrange polynomial evaluated at ghost positions.

The extrapolation is applied face-by-face in a sequential dimension sweep: X faces first, then Y faces, then Z faces. The loop ranges for the non-ghost directions must span the full array [0, Ntotal), not just the interior [ghost, ghost+N). This is what makes edge and corner cells work correctly. See the bug section for why this matters.

coarse_buf interior (+ earlier-sweep ghost data)coarse_buf domain-boundary ghost zonesEach fine leaf at domain boundary faces

Phase 4: Prolongate coarse_buf to Fine Ghosts

The final step: 5-point tensor-product Lagrange interpolation from the (now fully filled) coarse_buf into the fine block's ghost zones. For each fine ghost cell:

  1. Determine which neighbor direction this cell belongs to (ox, oy, oz).
  2. If that direction has a same-level neighbor, skip (Phase 0+1 already filled it).
  3. If it's a domain boundary, skip (Sommerfeld BCs handle it on the fine grid).
  4. Otherwise, map the fine index to a continuous coarse_buf index and interpolate with a 5x5x5 stencil.
ReadsWritesScope
coarse_buf (interior + ghosts, all filled)Fine block ghost zones (fields[])Ghost cells facing coarser neighbors only

The 5-point stencil needs 2 cells of padding around the interpolation point. This is why coarse_buf has a ghost width of 4 (= GHOST_WIDTH) — plenty of room for the stencil.

The Dimension-Sweep Bug Root Cause

This was the root cause of Test 6 failure: max_err = 0.386 (threshold = 9.8e-5). The error appeared at domain boundary corners where the prolongation stencil read unfilled coarse_buf ghost cells.

Diagnosis: The Unfilled Corner Problem

Consider a fine block at a domain corner, where x- is a domain boundary and z+ has a coarser neighbor. The coarse_buf has ghost zones that need filling on both sides.

What Phase 3 fills (and doesn't fill)

When copy_from_coarse_grid() fills the z+ ghost slab from the coarser neighbor, it calls ghost_range() for each direction:

ghost_range(ox=0, ...)  // x direction: offset 0 (not a ghost dir)
                        // returns INTERIOR range: [ghost, ghost+N)

ghost_range(oy=0, ...)  // y direction: offset 0
                        // returns INTERIOR range: [ghost, ghost+N)

ghost_range(oz=+1, ...) // z direction: offset +1 (ghost dir)
                        // returns GHOST range: [ghost+N, Ntotal)

So the z+ ghost slab is only filled for x in [ghost, ghost+N) and y in [ghost, ghost+N) — the interior range. Cells at x-ghost positions [0, ghost) within the z+ slab are not filled by Phase 3.

What Phase 3.5 fills (and doesn't fill)

Phase 3.5 processes domain boundary faces only. If x- is a domain boundary, it fills the x- ghost slab. But it does NOT process the z+ face (z+ has a coarser neighbor, not a domain boundary).

Result: the cell at position (x_ghost, y_interior, z_ghost+) is never filled by anything.

2D slice of coarse_buf (x-z plane)

This diagram shows which phase fills each region of the coarse_buf, viewed as an x-z slice. The x- face is a domain boundary; the z+ face has a coarser neighbor.

Neither Phase 3 nor Phase 3.5 reaches it. The prolongation stencil in Phase 4 reads this cell and gets garbage.

In 3D, this problem is even worse: a triple-corner cell at (x_ghost, y_ghost, z_ghost+) where x- and y- are domain boundaries but z+ is a coarse neighbor has three unfilled dimensions. The 5-point prolongation stencil reads multiple unfilled cells, producing the observed O(1) error.

The Fix: Full-Width Loop Ranges

The fix is to widen Phase 3.5's loop ranges in the non-ghost directions from the interior range [ghost, ghost+N) to the full array range [0, Ntotal). This matches AthenaK's BCHelper implementation, which uses n1, n2, n3 (full grid dimensions including ghosts) in its dimension-by-dimension sweep loops.

The sequential ordering (X, then Y, then Z) ensures correctness automatically:

Dimension-by-dimension sweep with full-width ranges: X sweep: extrapolate X-boundary ghosts for j = [0, Nt), k = [0, Nt) Fills X ghost cells at ALL y and z positions, including y-ghost and z-ghost regions. Y sweep: extrapolate Y-boundary ghosts for i = [0, Nt), k = [0, Nt) When it reads an X-ghost position, that value was already set by the X sweep above. Z sweep: extrapolate Z-boundary ghosts for i = [0, Nt), j = [0, Nt) When it reads an X-ghost or Y-ghost position, those values were already set by the X and Y sweeps above.

The Sweep Chain for a Triple-Boundary Corner

Consider a corner cell at (i_ghost, j_ghost, k_ghost) where all three faces are domain boundaries. The dimension sweep fills it through a chain of dependencies:

Reading order for corner cell (i_ghost, j_ghost, k_ghost): Z sweep writes (i_ghost, j_ghost, k_ghost) reads (i_ghost, j_ghost, k_interior) // where did this value come from? | +--> Y sweep wrote (i_ghost, j_ghost, k_interior) reads (i_ghost, j_interior, k_interior) // and this one? | +--> X sweep wrote (i_ghost, j_interior, k_interior) reads (i_interior, j_interior, k_interior) | +--> INTERIOR DATA (always valid from Phase 2) Each sweep's output feeds the next sweep's input. The chain terminates at interior data, which was filled by restriction in Phase 2. No cell is left unfilled, regardless of how many boundary faces meet at the corner.

This pattern — sequential dimension sweeps with full-width loops — is a standard technique for filling edge and corner ghost cells without explicit edge/corner handling. AthenaK's BCHelper in z4c_bcs.cpp uses exactly this approach.

Code Diff

The fix is a 4-line change in fill_coarse_buf_boundary(). The X-face loops already had full-width ranges for j and k (they were correct from the start). The Y-face loops needed widening for i and k, and the Z-face loops needed widening for i and j.

In practice, the original (buggy) code used interior-only ranges [ghost, ghost+N) in the non-ghost directions. The fix widens them to [0, Ntotal):

--- a/src/amr/ghost_exchange.c (buggy: interior-only ranges) +++ b/src/amr/ghost_exchange.c (fixed: full-width ranges) /* Y-faces: extrapolate in j */ if (b->nblevel[1][0][1] < 0) { /* y- boundary */ - for (int k = ghost; k < ghost + N; k++) { - for (int i = ghost; i < ghost + N; i++) { + for (int k = 0; k < Nt; k++) { + for (int i = 0; i < Nt; i++) { for (int d = 0; d < gh; d++) { ... if (b->nblevel[1][2][1] < 0) { /* y+ boundary */ - for (int k = ghost; k < ghost + N; k++) { - for (int i = ghost; i < ghost + N; i++) { + for (int k = 0; k < Nt; k++) { + for (int i = 0; i < Nt; i++) { for (int d = 0; d < gh; d++) { ...

The X-face and Z-face loops were already using [0, Nt) for their non-ghost directions, so they required no changes. Only the Y-face loops had the narrower ranges.

After the fix, the X sweep writes valid data into the x-ghost columns for all j,k. The Y sweep then reads those x-ghost values when extrapolating y-boundary ghosts, and the Z sweep reads both x- and y-ghost values when extrapolating z-boundary ghosts. Edge and corner cells are filled transitively.
