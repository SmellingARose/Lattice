Lattice vs. Production NR Codes

Last updated: 2026-04-02. Post cubic Taylor temporal interpolation implementation.

Comprehensive comparison of Lattice's numerical methods and architecture against all major production numerical relativity codes. Covers accuracy-critical choices in AMR subcycling, finite differences, boundary conditions, temporal interpolation, initial data, and GPU acceleration.

Codes compared: GRChombo (Chombo), BAM, SpEC, CarpetX/Einstein Toolkit (AMReX), AthenaK (Kokkos), Dendro-GR (wavelet), NRPy+ (code generation), Lean (Carpet).

4. Restriction (Fine → Coarse)

All FD AMR codes use simple cell averaging (2×2×2 = 8 fine cells, weight 1/8 each). Lattice previously used 6th-order Lagrange restriction (negative weights caused Gibbs oscillations near puncture singularities); switched to cell averaging to match GRChombo.

Chombo coefficient matrix (coeffs[term][stage] × dt):

        k1     k2     k3     k4
a1:     1      0      0      0
a2:    -3/2    1      1     -1/2
a3:     2/3   -2/3   -2/3    2/3

Evaluation: U(θ) = U_n + θ*(a1 + θ*(a2 + θ*a3)) (Horner form, 3 FMA per point).

15. Unique Features

Features found in Lattice but not in any single other code:

  1. CCZ4 + Einstein-Maxwell + charged puncture initial data + N-body solver in one codebase
  2. CK45 low-storage RK4 as a runtime switch
  3. HiSpID 4-field coupled multigrid for high-spin initial data
  4. Equidistribution-optimal AMR refinement ratio β = 23/5 ≈ 1.516
  5. Compile-time EM dispatch (COMPILED_NUM_FIELDS)
  6. Pre-computed prolongation weight tables verified bit-exact
  7. Zero-PCIe Berger-Oliger subcycling with cubic Taylor temporal interpolation on GPU
